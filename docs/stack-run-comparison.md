# 4320 두 평가의 규칙별 결과 비교

4310의 `/v1/compare`에서 제공하던 두 평가 확인 작업을 4320의 평가 근거 화면으로 옮기는 첫 범위다. 현재 선택한 평가와 같은 조직·프로젝트의 다른 완료 평가 ID를 입력하면 규칙별 기준/대상 결과, 필수 여부와 변경 개수를 나란히 표시한다. 최근 목록의 ID를 제안하며 과거 평가의 정확한 ID도 입력할 수 있다.

## API·권한·화면

- Console `GET /backend/runs/{candidate}/comparison/{baseline}` → Gateway → Core `GET /api/runs/{candidate}/comparison/{baseline}` 경로만 허용한다. POST/PUT/DELETE는 허용하지 않는다.
- 관리자·편집자·조회자 모두 자기 프로젝트의 완료 평가를 조회할 수 있다. 원래 `RunService.get`의 조직·프로젝트 범위를 두 ID에 각각 적용하고 반환 scope도 확인한다. 타 범위·없는 평가는 404, 미완료 평가는 409, 같은 ID는 400이다.
- DB 쓰기·스키마 변경·새 평가·검토·승인은 없다. 각 평가의 규칙은 최대 100개, 비교 표는 합집합 최대 200개다. 중복/잘못된 규칙은 결과를 표시하지 않는다. 한쪽에 없는 규칙은 명시적으로 `규칙 없음`으로 표시한다.
- 화면은 현재 평가·기준 ID·계정 범위 변경 시 이전 결과와 진행 요청을 폐기한다. 응답의 두 ID·조직·프로젝트·규칙 정렬·개수·변경 여부를 확인한 뒤 표시한다.

## 지원 범위

이 기능은 **관측된 규칙 결과 비교**다. 4310 비교의 동일 데이터셋·정책 snapshot/서명 검증과 현재 게이트 판정을 자동 이전한 것은 아니다. 서로 다른 입력과 정책에서 얻은 결과를 회귀 통과로 취급하지 않는다. 응답은 `deploymentAuthority=false`, `regressionAuthority=false`이며 현재 게이트는 별도로 조회한다. 동일성에 결합된 전체 회귀 판정의 이전은 후속 작업이다.

## 검증과 적용

Core 서비스·HTTP 권한 및 Gateway 경로 테스트, Console 응답 계약·경로·타입 검사와 실제 후보 브라우저 시나리오를 포함한다. 브라우저 시나리오는 일회성 CI의 실제 두 완료 평가를 조회하고, 다른 scope로 치환된 응답을 표시하지 않는지 확인한다. 로컬 원본·실행 중인 복구 서비스에는 새 코드를 적용하지 않는다. 후보 CI와 실제 배포 결과는 별도로 기록한다.
