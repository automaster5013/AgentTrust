# 전체 저장 버전의 정확한 이름 검색

현재 페이지의 최대 25개 이름 필터와 별도로, 현재 조직·프로젝트의 에이전트 또는 데이터셋 저장 이력 전체를 정확한 `resourceKey`로 탐색한다. 이름은 등록 계약과 동일한 3~64자의 영문 소문자·숫자·하이픈이다. 부분 문자열·의미 검색·프로젝트 간 검색은 제공하지 않는다.

Java `VersionHistoryReader`가 강제 RLS 범위 안에서 이름을 SQL 파라미터로 결합하고 `created_at DESC,id DESC` 순서로 26개를 읽어 최대 25개와 다음 경계를 반환한다. `version-history-search/{agents|datasets}/{name}[/{cursor}]`는 Gateway와 BFF에서 인증된 GET만 허용한다. 쿼리 문자열이나 쓰기 요청은 거부한다. DB migration과 기존 API의 응답 계약 변경은 없다.

검색 커서는 이름의 SHA-256과 기존 조직·프로젝트·종류·마이크로초·UUID 경계를 결합한다. 이는 탐색 좌표이며 비밀 서명이나 현재 배포 권한이 아니다. 서버와 TypeScript는 이름·범위·종류가 바뀐 경계, 잘못된 정렬·중복·다른 이름의 행·치환된 다음 커서를 거부한다. 기존 버전 선택 경로에서 원본 내용·해시·활성 상태를 다시 확인하므로 폐기된 버전은 과거 검색에 나타나더라도 새 캠페인 실행 선택에 사용할 수 없다.

화면은 이름 편집 시 진행 중인 조회를 취소하고 결과·페이지 경계를 지운다. 실패나 검증 불가 응답은 빈 결과 성공으로 취급하지 않고 이전 행도 지운다. 검색 요청을 지원하지 않는 이전 Core에서는 미지원 가능성을 표시한다. 검색이나 실패는 이미 선택한 실행 버전을 바꾸거나 평가를 생성하지 않는다.

## 검증 범위

- 이름·종류·테넌트·마이크로초 경계와 잘못된 경로/쓰기 거부의 Java 및 TypeScript 계약 검사.
- hosted 합성 fixture에서 종류별 한 이름에 27개 불변 버전을 등록한다. 유료 모델이나 평가 실행은 호출하지 않는다.
- 실제 브라우저에서 25+2 페이지·이전 페이지 복귀·오래된 버전의 내용/해시/활성 상태 확인 후 선택·이름 치환 및 HTTP503의 이전 행 제거·정확한 빈 결과를 검사한다. 이전 Core는 실제 미지원 응답 표시를 별도로 검사한다.
- Python 읽기 전용 대조가 종류별 최소 한 개의 실제 여러 페이지를 요구하고 독립 PostgreSQL 순서·시각·내용 좌표·다른 조직/이름/종류 경계 거부와 업무 테이블 보존·본인 세션 로그아웃을 검증한다.

로컬 콘솔 계약·타입·Java 검사는 통과했다. 실제 hosted CI의 성공과 원본 artifact/source 결합 수용은 해당 소스 revision의 별도 증거를 따른다. 운영 Core/Gateway 교체·운영 자료 이전·범용 에이전트/데이터셋·전체 기능 이전·운영 복구/SLO 완료를 뜻하지 않는다.
