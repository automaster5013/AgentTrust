# 프로젝트 감사 기록 내보내기

`GET /api/audit-export`는 현재 인증된 조직·프로젝트의 최신 감사 메타데이터를 한 SQL 문장의 스냅샷으로 읽는다. PostgreSQL RLS와 명시적 조직·프로젝트 조건을 적용하며 조회자의 역할도 사용할 수 있다. 경로·질의로 다른 조직을 선택하거나 POST로 기록을 변경할 수 없다. API 역할의 기존 감사 UPDATE/DELETE 제한을 유지하고, 내보내기로 새 감사 행을 쓰지 않는다.

최신 500개를 시간·ID 내림차순으로 반환한다. 501번째 행의 존재로 `hasOlderRecords`를 판별하며, 500개를 넘으면 `entireProjectHistory`는 false다. 정확히 500개 이하이면 해당 SQL 문장의 조회 시점에서 전체 기록을 포함했다는 뜻이다. 이후 추가된 기록까지 포함하는 지속적 완전성 증명은 아니다. 첫·마지막 실제 기록의 조직·프로젝트·마이크로초 시각·ID를 경계로 묶는다.

응답은 최대 256KiB인 UTF-8 `contentJson`의 원문, SHA-256, 바이트 수와 인증된 범위를 포함한다. 기존 16KiB 평가 보관·서명 계약을 확대하지 않는다. 비밀·검토 사유·모델 입력·원본 출력은 포함하지 않으며, 감사 ID·작업자 ID·작업·대상 ID·시간만 내보낸다.

TypeScript는 해시·바이트 수·조직·프로젝트·스키마·최대 행 수·중복·전체 순서·실제 경계·포함 범위의 모순을 확인한 뒤 JSON 파일을 만든다. 실패하면 파일을 내려받지 않는다. 화면에는 이전 기록이 더 있는지 표시한다. 서버가 보내온 파일 해시는 내려받은 바이트를 확인하기 위한 값이며 독립 발급자의 진위를 입증하는 서명이 아니다. 파일과 응답의 `signed` 및 `currentDeploymentAuthority`는 항상 false다. 독립 감사 서명·운영 보존·전체 이력의 대량 내보내기는 남은 작업이다.

2026-10-12 로컬에서 Java 97개, WebFlux 23개, TypeScript 78개 검사와 TypeScript 타입 검사가 통과했다. `python scripts/stack-audit-export-smoke.py`의 실제 OIDC·API·RLS 검증 4개 묶음과 전체 브라우저 검사 22개가 통과했다. 501개 동일 시각 테스트 기록의 최신 500개와 후속 추가의 스냅샷 보존을 확인했다. 서비스 적용 전후 업무 테이블 16개는 동일했고, 자체 합성 기록을 추가한 후에도 창 시작 이전 업무 테이블 14개의 원본 행 해시를 보존했다. 이 변경의 GitHub CI와 게시 이미지 결과는 해당 revision의 실행 결과로 별도 확인한다.

반복 읽기 검사는 `python scripts/stack-readonly-soak.py --minutes 180 --readers 20 --audit-export`로 내보내기를 포함한 11개 경로를 관찰할 수 있다. 별도 공개키 검토는 `stack-signed-review-soak.py --minutes 120 --campaign <UUID> --require-baseline`으로 기존 기준 결합 캠페인의 범위·부모·자식 바이트 및 기준 조건 해시를 반복 검증한다. 실행·승인·추론을 요청하지 않고 완료 시 업무 테이블의 전후 해시와 자체 세션 종료를 확인한다. 명령을 지원하는 것과 해당 기간의 관찰을 완료하는 것은 별도 결과다.
