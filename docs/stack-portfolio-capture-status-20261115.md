# 실제 제품 시연 촬영 준비 결과 — 2026-11-15

## 현재 상태

실제 제품 화면의 촬영·영상·자막·공개 검토는 **미완료**다. 문서·도식 설명 영상으로 대체하지 않았다. [14개 기능 포트폴리오와 촬영 대본](stack-portfolio-accepted14.md)은 문서 준비 완료 상태를 유지한다.

사용자는 실제 촬영을 위한 로그인·격리 후보 실행과 촬영용 독립 환경 설치를 추가 허용했다. 기존 복구 WSL·서비스·원본 변경 금지, 거부된 소스 분리 작업 재시도 금지와 보안 검사 하향 금지는 유지한다. 기존 작업창 종료 이후 별도로 재개한 촬영 준비 결과다.

## 완료한 준비

- 메모리 재확인에서 가용 3.714GiB로 3.5GiB 입장 기준 충족을 확인했다. 확인 시점에 일반 앱을 강제 종료할 필요가 없어 종료하지 않았다. 이 수치는 후보 전체 부하 수용이나 지속 여유 증명이 아니다.
- 보존된 Alpine 3.24.4 rootfs 파일의 SHA256 `cdaa38cb8de3537967ee5b6c9b6cd00cc962da2b018e6eea48696bb274923012`를 기존 출처 기록과 대조했다.
- 별도 WSL `AgentTrustCapture-20261115`를 생성하고 Docker·Compose·Python·FFmpeg 등 촬영 환경용 도구를 설치했다. 기존 복구 WSL을 설치·셋업 대상으로 사용하지 않았다.
- 수용된 정확 소스 `23c810c769a59477308d3fd3df7aba39c2487bb4`를 Git archive로 촬영 환경에 준비했다. 아카이브 SHA256은 `bb90dab934e48413c528c7037596b8c1c137d907ebff71a1b17c95fe86262d22`다. 새 개발 브랜치·clone·worktree를 만들지 않았고, 현재 개발 사본의 미검증 connector worker 변경을 포함하지 않았다.
- 새 Docker 엔진은 촬영 환경 전용 socket·data-root·exec-root·pidfile을 사용했다. 기본 bridge와 iptables/ip6tables·IP forwarding·masquerade 변경을 비활성화했다. 제품 서비스의 외부 포트를 게시하지 않았다.

## 보존과 후속 조건

준비한 독립 환경과 설치 파일은 보존한다. 빌드 실패 후 촬영용 Docker daemon만 자신의 pidfile과 명령행을 확인해 종료했다. 기존 복구 WSL·서비스에 중지·재시작·설정 변경을 하지 않았다. 현재 개발 사본의 미검증 한 줄 변경은 커밋하지 않았다.

실제 촬영을 재개하려면 필수 이미지의 보안 기준을 충족하는 빌드 경로가 필요하다. 이는 현재 허용된 환경 설치만으로 해결됐다고 볼 수 없으며, 금지된 소스 분리 작업의 우회·재시도나 미수용 소스를 수용 완료로 표시해 해결하지 않는다.

영상·실제 화면 캡처·동기화 자막·공개 검토 결과가 없으므로 전체 포트폴리오 제작 완료로 보고하지 않는다. 현재 제품 버전의 공개 가능성·최종 영상 노출 검토도 미확인이다.
