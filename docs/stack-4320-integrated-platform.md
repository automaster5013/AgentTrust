# 4320 최종 통합 플랫폼

2026-10-31 사용자 정정: 최종 AgentTrust는 `http://127.0.0.1:4320`의 **Next.js/TypeScript + Java/Spring Boot + Python/FastAPI** 플랫폼이다. 기존 4310의 사이드바·작업 흐름을 새 스택으로 구현하며, 4310 자체로 주소를 옮기지 않는다. [이전 4310 주소 인계 제안](stack-4310-single-entry-transition.md)은 폐기했다.

## 이번 소스 구현

기존 새 콘솔의 기능/인증 경로를 그대로 사용하는 통합 작업공간을 확장했다.

| 사이드바 | 연결된 기능 | 경계 |
|---|---|---|
| 프로젝트 홈 | 현재 인증된 프로젝트의 최근 평가 건수·판정별 건수·진행 중 건수, 주요 작업 바로가기 | 조회한 최대 50개 표본만 요약. 로딩/실패는 0건이 아닌 미확인. 통과 건수는 현재 배포 허용 건수가 아님 |
| 평가 실행·조회 | 기존 Java API의 평가 생성·목록·근거·보관본·취소·검토·현재 게이트 | 기존 조회자/편집자/관리자 권한, 요청 scope·멱등성·검토 근거 보호 유지 |
| 버전·캠페인 | 기존 불변 버전·캠페인·사례·회귀/보관 근거·검토 기능 | 아직 범용 기능/과거 4310 데이터 전체를 이전한 것은 아님 |
| 준비 상태·사용량 | 기존 readiness와 공급자 사용량 조회 | 연결 정상/예약 한도가 모델 성공·운영 준비 완료를 뜻하지 않음 |
| 이력·감사 | 기존 평가 이력·ID 조회·감사 조회/범위 검색 | 사용자 프로젝트 범위와 페이지 경계 유지 |
| 플랫폼 지원 범위 | 4320의 현재 기능과 4310 자료 보존·미이전 기능 설명 | 없는 기능을 작동 버튼으로 제공하지 않음 |

사이드바는 넓은 화면에서 녹색 세로 rail, 좁은 화면에서 항목을 숨기지 않는 2~3열 메뉴으로 동작한다. 같은 페이지의 실제 기능 구역으로 이동하므로 메뉴 이동 때문에 입력/선택/진행 요청 컴포넌트를 재마운트하거나 평가를 중복 생성하지 않는다. 기존 상세의 관리자 검토·게이트 바로가기도 유지한다. 홈은 이미 검증한 평가 목록만 사용하며 추가 API/운영 자료 조회를 만들지 않는다.

## 주소·데이터·인증

- 4320 Console → BFF → 내부 Gateway → Java Core → Python/NATS/OPA의 원래 스택 경로를 유지한다. 기존 4310 API로 요청을 우회하거나 두 DB에 dual-write하지 않는다.
- 현재 4320 application origin과 4322 Keycloak issuer·PKCE·callback·쿠키·CSRF 계약을 보존한다. 최종 **제품 진입점**이 4320이라는 결정은 Keycloak·내부 API·관측 도구까지 같은 브라우저 origin으로 바꾼다는 뜻이 아니다. 이번 범위에는 OIDC 설정 변경이나 새 단일 origin 프로필이 없다.
- 기존 `agenttrust.*` DB와 새 `stack_*` DB는 별도다. 4310 계정/세션/접근 키/과거 승인/서명은 자동 승계하지 않는다. 새 화면에서 기존 데이터를 조회할 때는 별도의 읽기 전용 이전/검증 계약이 필요하다.
- 원래 바이트·hash·서명·신뢰 공개키를 보존하고 과거 기록을 새 현재 배포 권한으로 취급하지 않는다.

## 남은 기능 이전

[기능 이전 범위](stack-feature-parity.md)의 미완료 항목을 기준으로 구현한다. 특히 4310의 프로젝트 관리·접근 키 발급·세션 관리, 범용 에이전트/품질 데이터셋, 전체 이력 탐색과 기존 서명 자료 연결은 이 사이드바 구현으로 완료되지 않는다. 단순 링크/빈 패널로 완료 처리하지 않고 Java API·DB·권한 계약과 실제 화면 경로를 함께 검증한다.

우선순위:

1. 이번 통합 화면의 계약·타입·반응형/키보드 검사와 실제 후보의 브라우저 수용.
2. 기존/신규 자료 형식·조직/프로젝트/주체 mapping 및 서명 보존 계약, 합성 이력 연결 검증.
3. 핵심 미이전 과업을 하나씩 Java/Python/TypeScript의 실제 경로로 완성. 현재 지원 범위 표시를 함께 갱신.
4. 자원 기준·최신 source/path 검사·독립 사본/fresh reader·재인증 등 운영 복구 조건 충족.
5. 정확한 후보의 CI·이미지/서명·실행 검증 후 별도 운영 적용 검토. 4310 포트 인계는 하지 않음.

## 검증과 적용 상태

`scripts/console-ui-review.cjs`는 실제 Navigation/Overview/PlatformScope/DecisionSummary/Lookup 컴포넌트와 CSS를 합성 fixture로 렌더링한다. 미확인 건수·조회자 바로가기·부분 통계의 의미를 검사한다. 이 결과는 로그인된 전체 Workspace, Java/Python E2E 또는 현재 4320 설치의 적용 증거가 아니다. 실제 API 브라우저 시나리오는 `apps/console/e2e/workspace.spec.ts`에서 별도로 실행한다.

이번 로컬 확인: 콘솔 계약 테스트 161개와 TypeScript 검사 통과. 합성 구성요소의 360/390/768/1440px 화면에서 가로 넘침 없음, skip link와 6개 메뉴의 대상/키보드 초점 접근을 확인했다. 작은 화면에서 메뉴가 화면 밖으로 밀리는 초기 실패를 2~3열 메뉴로 수정한 후 네 크기 모두 통과했다. 실제 API의 목록 실패→미확인→재조회 응답에 결합된 건수 복구와 조회자 권한 시나리오는 추가했으나, 운영 4320에 적용하거나 해당 API E2E를 로컬에서 실행한 것은 아니다.

이번 작업은 **소스 구현**이다. 현재 서비스·컨테이너·DB·IdP·이미지·포트·자동 기동·현재 대화는 변경하지 않는다. 따라서 현재 실행 중인 4320이 이 변경을 이미 보여 준다고 주장하지 않는다. 기존 컨테이너의 ID/image/StartedAt을 모두 유지하면서 새 이미지를 배포할 수는 없으므로, 검증 후 운영 반영에는 별도 적용 단계가 필요하다.

실제 CD·건강한 롤백·전체 복구·기능 전체 이전은 계속 별도 미완료 조건이다. 원본과 복구 사본의 보존, 새 쓰기 전후 복귀 경계, 미완료 작업/멱등성/재인증 검증, 공개 CI에 운영 자료를 보내지 않는 정책을 유지한다. 메모리 부족을 이유로 안전 기준을 낮추거나 운영 서비스를 중지하지 않는다.
