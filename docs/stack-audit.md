# 새 스택의 프로젝트 감사 기록

Next.js 화면의 **프로젝트 감사 기록**에서 최신 기록을 조회하고 이전·다음 페이지로 이동한다. Java API는 로그인한 조직·프로젝트의 평가 요청/완료, 버전 등록, 승인/반려와 과거 판정 서명 기록을 반환한다. 조회자는 읽을 수 있고, 모든 역할의 감사 기록 수정·삭제 API는 제공하지 않는다.

`GET /api/audit`와 `GET /api/audit/{cursor}`는 최대 25개 기록을 반환한다. Spring WebFlux Gateway의 인증·Redis 읽기 한도를 경유하고, Core의 제한된 PostgreSQL 역할 및 행 수준 보안으로 범위를 다시 제한한다. `.local` 계정 파일이나 비밀번호, 모델 입력/응답, 검토 사유는 응답에 포함하지 않는다. 작업자와 대상은 기록된 UUID로 표시한다.

페이지는 PostgreSQL의 `created_at DESC,id DESC` 순서다. 커서는 조직·프로젝트 UUID, 원래 시각의 마이크로초와 마지막 기록 UUID를 담은 고정 80자 base64url 경계다. 별도 자격 증명이나 서명된 증거가 아니며, 인증된 범위를 바꿀 수 없다. SQL은 바인딩된 값과 고정 26개 한도로 다음 페이지 존재 여부를 확인한다. 동일 시각의 여러 기록을 UUID로 구분하며, offset 이동을 사용하지 않는다.

브라우저도 응답 범위·필드·정렬·중복·시간 정밀도·요청 경계와 다음 커서의 마지막 기록 결합을 확인한다. 오류가 발생하면 이전 페이지 내용을 지우고 재조회를 안내한다. 계정/범위 변경에는 새 컴포넌트를 사용한다.

조회 중 새 기록이 추가될 수 있다. 최신 조회로 시작한 각 탐색은 동결된 전체 내역 export, 트랜잭션 스냅샷, 감사 서명 또는 배포 승인이 아니다. 오래된 페이지 경계보다 뒤에 추가된 최신 기록은 새로 조회해야 나타난다. 운영 감사 보존 정책·대량 내보내기·독립 서명 검증은 별도 범위다.

```powershell
python scripts/stack-audit-smoke.py
```

검사는 새 스택의 자체 합성 감사 기록만 추가한다. 같은 시각의 27개 기록에 대한 페이지 이동, 탐색 중 새 기록 추가, 조회자 읽기·다른 조직/프로젝트 거부, 잘못된 커서·쓰기 경로 거부와 DB 역할의 UPDATE/DELETE 거부를 확인한다. 기존 기록을 정리하거나 변경하지 않는다. 집중적인 HTTP 검사를 동시에 실행하지 않는다. 실제 Keycloak 로그인·브라우저 페이지 이동·조회 오류 후 복구는 Playwright 검사에 포함한다.
