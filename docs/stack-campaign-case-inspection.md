# 캠페인 사례별 평가 근거 확인

4310 renderEvidence의 사례별 규칙·근거 확인 작업을 현재 4320 계약으로 이전한다. 기존 CampaignCaseEvidence의 요약·필터에 종료 사례 선택과 명시적 근거 조회를 연결한다. API·권한은 기존 인증 GET `/api/campaigns/{id}`와 `/api/runs/{childRunId}`를 그대로 사용한다. 조회자도 읽을 수 있으며 새로운 쓰기·계정·인증·DB 설정은 없다.

먼저 fresh 부모를 verifiedCampaign으로 검증하여 조직·프로젝트, 버전 SHA256, 프로필 해시, 전체 사례 정의·연결을 확인한다. 화면에 선택된 부모의 불변 좌표·버전 정의·시간·승인 필요 여부와 선택 사례의 caseId/required/runId/provider/scenario/state/decision이 모두 일치해야 한다. 그 뒤에만 자식 GET을 호출하고 기존 detail 계약으로 scope/ID/규칙 수·필드·엔진을 검증한다. 자식의 provider/scenario/state/decision/requires_approval도 부모 선택과 일치해야 한다. 다른 사례가 비동기로 완료돼도 선택한 종료 사례와 불변 부모의 결합은 유지해야 한다.

규칙 id·필수 여부·관측 상태·이유·실행 엔진을 React 텍스트로 표시한다. 정답 데이터셋의 고정 입력·기대 답안이 있으면 기존 바이트 한도로 검증된 정의를 텍스트로 표시한다. 현재 detail 계약에 없는 원시 모델 출력·도구 이벤트는 제공하지 않는다. 인증 API의 정규화된 관측이며 독립 서명·원본 바이트·MinIO 보관 검증은 아니다. 현재 게이트·검토·서명·배포 권한은 별도다.

대기 사례는 조회할 수 없다. 선택·부모 재조회·필터·범위·역할 변경, 오류, 취소 시 상세를 제거하고 늦은 응답을 거부한다. 부모의 소속이나 내용 검증 실패 시 자식 조회도 시작하지 않는다. 기존 전체 캠페인 판정과 게이트는 필터로 바뀌지 않는다.

로컬 Console 205건·TypeScript·actionlint 통과. 실제 소스 합성 브라우저 15항목·JS 오류 0: 부모/자식 순서, 규칙 텍스트·script/img 비실행, 범위·소속·버전·자식 ID·승인 필요 여부 치환, 401/503, 필터 제거, 취소·다른 사례·범위 변경 후 늦은 응답, 1440/390을 확인했다. 실제 backend 연결은 false이며 후보 수용을 대신하지 않는다. 후보 E2E는 기존 합성 캠페인·자식만 읽어 실제 규칙과 대조하고 익명 401·소속 검증 실패 시 자식 조회 0·업무 쓰기 0을 검증한다. 현재 복구 서비스에는 적용하지 않는다.
