# 작업과 대상별 감사 기록 검색

기업 개발팀은 특정 에이전트·데이터셋 버전의 등록과 폐기, 평가 요청과 관리자 검토 기록을 작업 종류와 대상 UUID로 찾을 수 있다. 기존 감사 조회와 JSON 내보내기는 유지한다. 검색은 읽기 전용이며 결과·승인·서명·보관본을 변경하지 않는다.

## API와 경계

`GET /api/audit-search/{action}/{resource}`는 첫 페이지를, `GET /api/audit-search/{action}/{resource}/{cursor}`는 다음 페이지를 반환한다. `all`은 해당 조건을 지정하지 않은 값이다. 작업은 서버의 14개 허용 항목, 대상은 소문자 정규 UUID로 제한한다. 알 수 없는 작업과 조건이 다른 커서는 400으로 거부한다.

Java API는 인증된 조직·프로젝트를 PostgreSQL 조회와 강제 RLS에 사용한다. 조건을 SQL 매개변수로 전달하며 최신순으로 최대 25개를 반환한다. 대상이 다른 조직에 있으면 기록을 반환하지 않는다. 외부 조직·프로젝트의 커서는 재사용할 수 없다.

검색 커서는 버전 1, 정규 검색 조건의 SHA-256, 기존 조직·프로젝트·마이크로초 시각·기록 ID 경계를 93바이트로 묶는다. 124자의 정규 base64url만 허용한다. 페이지 응답은 실제 조건을 명시한다. 커서는 탐색 경계이며 인증 자격이나 전체 기록의 증명이 아니다.

## 화면과 검증

Next.js 화면은 작업 종류와 대상 ID를 입력받는다. 조건 변경 시 이전 결과와 커서를 지우고 진행 중인 요청을 취소한다. 응답의 조건·범위·정렬·중복·행별 조건 및 다음 커서의 마지막 행 결합을 검증한 뒤 표시한다. 이전·다음 페이지 이동을 지원한다. 기존 JSON 내보내기는 검색 결과가 아닌 프로젝트의 최신 500개 기록을 대상으로 한다.

`python scripts/stack-audit-search-smoke.py`는 기존 기록만 읽어 조회자·관리자 검색, 서로 다른 페이지, 조건 변경 커서 거부, 외부 조직의 대상·커서 거부, TypeScript의 치환 응답 거부 및 18개 업무 테이블 보존과 세션 로그아웃을 확인한다. 실제 브라우저 검사는 검색·조건 변경·페이지 왕복·치환 응답 거부와 진행 중인 검색 취소를 수행한다. 이전 응답을 보류한 채 새 조건의 검색을 완료한 뒤 보류 응답을 전달해도 새 결과가 유지되는지 확인하며, 390px 화면의 문서 가로 넘침도 검사한다. CI는 소스와 게시 이미지에서 같은 API 검사를 실행한다.

로컬 API와 브라우저 통합을 검증했다. 새 revision의 CI·게시 이미지·보안 증거는 별도 확인한다. 기간 필터, 전체 이력 내보내기, 독립 감사 서명과 운영 보존 정책은 아직 구현하지 않았다.

잘못된 대상 UUID는 서버 요청을 보내기 전에 거부한다. 서버가 503을 반환하면 이전 결과를 표시하지 않고 재검색 버튼을 다시 활성화한다. 브라우저 검사는 오류를 주입한 뒤 실제 API로 수동 재검색해 정상 결과가 돌아오는지 확인한다. 자동 재시도나 업무 데이터 쓰기는 수행하지 않는다.

평가 요청·완료·취소와 평가 검토의 검색 행에는 해당 평가의 상세를 여는 버튼을 제공한다. 검증한 행의 대상 UUID를 기존 조직·프로젝트 범위 상세 조회에 전달하며 이전 평가의 근거와 판정은 지운 뒤 새 결과를 확인한다. 버전·캠페인·과거 서명과 알 수 없는 작업의 대상 ID는 평가로 해석하지 않는다. 조회자가 상세를 열어도 검토·승인 권한을 얻지 않는다. 이 연결은 기존 기록을 읽으며 평가나 검토를 생성하지 않는다.

평가 상세 선택은 상세와 현재 게이트 조회에 같은 10초 제한을 적용한다. 다른 평가로 선택이 바뀌면 이전 상세 응답으로 게이트 요청을 시작하지 않으며, 시간 제한이나 조회 실패 시 이전 근거·판정을 복원하지 않는다. 사용자는 같은 기록을 다시 선택해 실제 API로 재조회할 수 있다.


## 2026-11-03 전체 저장 이력 작업자 검색 — 소스 구현

선택적인 정확한 소문자 작업자 UUID를 입력하면 현재 페이지가 아닌 현재 프로젝트의 전체 저장 감사 이력에서 작업·대상 조건과 함께 검색한다. `GET /api/audit-actor-search/{actor}/{action}/{resource}[/{cursor}]`는 기존 RLS·매개변수 SQL·25개 keyset 순서를 사용한다. 기존 `/api/audit-search`의 응답·124자 커서는 변경하지 않는다. 새 168자 커서는 작업자 지문의 33바이트와 기존 조건/범위 경계 93바이트를 묶으며 다른 작업자·조건·조직·프로젝트의 탐색에 재사용할 수 없다. 이는 서명이나 권한 증명이 아니다.

화면의 `전체 이력 작업자 ID`와 기존 `현재 페이지 작업자 필터`는 구분된다. 검색 변경·실패·취소는 이전 결과를 지우며 지연된 응답을 복원하지 않는다. 이전 Core의 404는 미지원으로 표시하고 작업자 조건을 비워 기존 검색을 사용할 수 있다. 프로젝트의 최신 500개 JSON 내보내기 계약은 유지한다.

로컬 TypeScript 계약 검사와 타입 검사, Java 커서·Gateway 경로 검사를 수행했다. Python 실제 DB 행/순서 대조·다중 페이지·외부 조직/변경 커서 거부와 실제 브라우저 경로를 추가했지만 해당 새 소스의 hosted CI·운영 적용은 아직 미검증이다. DB schema·마이그레이션·업무 쓰기는 추가하지 않았다.


### 정확한 개발 브랜치의 hosted 검증

PR 작성 연결 권한이 없는 경우에도 `codex/audit-actor-search-20261103` 한 브랜치의 push로 같은 6개 검증 workflow를 실행한다. wildcard나 다른 브랜치를 허용하지 않고 기존 job·검사·권한·수동 실행 및 게시 조건은 유지한다. 이 경로는 PR/merge 검증과 구분해 정확한 push 소스 SHA·원본 artifact digest·실제 결과에 결합한다. main 병합이나 운영 적용은 수행하지 않는다.


## 2026-11-04 UTC 날짜 기간 검색 — 소스 구현

`감사 UTC 시작일`과 `감사 UTC 종료일`을 모두 입력하면 양 끝 날짜를 포함해 최대 366일의 저장 이력을 검색한다. UTC 날짜이며 한국 시간 날짜로 자동 해석하지 않는다. 두 날짜를 모두 비우면 기존 검색을 사용한다. 정확한 작업자 UUID·작업 종류·대상 ID와 교집합으로 조회하며 현재 페이지 표시 필터와 구분한다. 지원 날짜는 1970-01-01부터 9999-12-30까지다.

`GET /api/audit-period-search/{start}/{end}/{actor}/{action}/{resource}[/{cursor}]`는 Java의 강제 RLS와 매개변수 SQL에서 시작일 00:00 UTC 이상, 종료일 다음 날 00:00 UTC 미만을 사용한다. DB schema나 migration·쓰기·기존 검색/내보내기 계약은 변경하지 않는다. 새 124자 커서는 schema2와 전체 기간·작업자·조건 지문, 조직·프로젝트·마이크로초 시각·ID를 결합한다. 이전 검색 커서는 길이가 같아도 schema/조건 결합이 달라 재사용하지 못한다. 기간 밖의 경계·행·응답 조건 치환도 거부한다.

화면은 부분 날짜·잘못된 날짜·역순·366일 초과를 요청 전에 거부하고 조건 변경·취소·실패 시 이전 결과를 지운다. 이전 Core의 기간 검색은 미지원으로 남으며 두 날짜를 비워 기존 검색으로 복귀할 수 있다. Python의 실제 PostgreSQL 전체 ID/정렬 대조·페이지·날짜/행위자/조건/외부 조직 커서 거부와 실제 브라우저의 일자 검색·페이지 이동·응답 치환·실패 복귀 시나리오를 추가했다. 새 소스의 hosted CI와 운영 적용은 별도 검증 대상이며 전체 이전이나 독립 감사 서명 완료가 아니다.


기간 감사 JSON 구간 내보내기 소스 구현: UTC 기간과 작업자·작업·대상 조건을 고정한 GET `/api/audit-period-export/{start}/{end}/{actor}/{action}/{resource}[/{cursor}]`는 최대 250개 메타데이터를 한 파일로 반환한다. 다음 커서로 기존 최신 500건 한도를 넘겨 순회하며 기존 500건 내보내기는 유지한다. 각 파일은 별도 SELECT의 결과이므로 여러 파일을 한 시점의 스냅샷·전체 프로젝트 이력·서명된 증거로 표시하지 않는다. 브라우저는 범위·정렬·커서·정확한 UTF-8 바이트와 SHA-256을 검증한 뒤 다운로드하며 취소/조건 변경 후 지연 응답을 폐기한다. 소스 검증 및 hosted CI 수용은 별도 기록하며 운영 Core/Gateway 적용은 미수행이다.
