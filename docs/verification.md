# v0.2 검증 기록

완료일: 2026-10-04 (Asia/Seoul). 모든 작업·명령의 작업 디렉터리는 C:\AgentTrust다.

## 자동 검증

Windows / Node.js 24.15.0 / Docker Desktop의 PostgreSQL 17에서 JavaScript 문법 검사와 26개 테스트가 모두 통과했다. 테스트는 agenttrust_test DB를 사용하며 운영 개발 DB와 분리했다.

- 모의 7개 모드 평가와 필수 규칙, JSON 스키마·도구 인자 검사, 입력 중첩/크기 제한.
- 조직 간 버전·실행·결과·게이트·취소 접근 거절, DB RLS로 타 조직 행 조회·삽입 거절.
- viewer/editor/admin 역할, 익명·만료·폐기·로그아웃 세션 거절, 동시 로그인 세션 한도.
- 동시 멱등 요청 8개의 실행 ID가 하나로 수렴하고 조직별 같은 키는 분리됨.
- 새 DB 연결 후 버전/실행 보존, 버전 수정 권한 거절, 종료 결과 수정 트리거 거절.
- 워커 동시 점유, 만료 lease 재점유, 이전 시도 결과 fencing, 중복 완료·계량 거절.
- 대기/실행 중 취소, 시간/사례 예산 초과, 시도 소진은 배포를 허용하지 않음.
- 감사 기록은 자기 조직에 한정되고 원문 키·사례 내용을 포함하지 않으며 API에서 삭제 불가.
- Origin/Host/JSON/헤더/과대 본문/비허용 파일 거절과 CSP/텍스트 출력 경로.

npm audit는 검사 시점 알려진 취약점 0건이었다. npm ci를 포함한 Docker 이미지 빌드도 성공했다. 원격 GitHub Actions 실행과 배포는 아직 수행하지 않았다. 워크플로에는 실행별 Compose 이름, PostgreSQL 준비, 테스트·감사·이미지 빌드를 구성하고 공식 actions의 확인한 v7 커밋을 고정했다.

## 실제 Docker 검증

agenttrust-api-1, agenttrust-db-1, agenttrust-worker-1을 구동했다. 호스트에 공개한 포트는 루프백 4310/55432뿐이다. API와 워커는 서로 다른 컨테이너와 DB 역할로 실행한다. DB 소유자 자격은 런타임 API/워커에 전달하지 않았다.

smoke.mjs before로 인증된 평가를 저장해 PASS를 확인했다. AgentTrust 컨테이너 3개를 모두 정지·재시작한 후 after 검증에서 실행 결과·스냅샷·결과 해시가 유지됐고 사용량과 완료 감사 이벤트가 중복되지 않았다.

## 브라우저 검증

관리자 로그인, 정상 평가와 감사 표시, 느린 실행의 취소, 500ms 시간 초과의 INCONCLUSIVE/배포 허용 안 함을 확인했다. 조회자 로그인에서 실행·데이터셋 등록이 비활성화되고 감사 패널이 숨겨지는 것을 확인했다. 로그인 입력 키는 성공 후 지워졌다. 다른 조직으로 로그인한 화면에는 기존 조직의 실행 기록과 스냅샷이 표시되지 않았다.

v0.1의 스크립트 출력이 문자 그대로 표시되는 검증 기록과 화면은 evidence/local-evaluation.jpg에 보존했다. v0.2 정상 평가 완료 화면은 evidence/persistent-evaluation.jpg에 저장했다.

## 보존과 남은 범위

LogiTrack 컨테이너 12개는 정지했고 기존 볼륨 7개와 현재 자체 이미지 태그 5개를 조회했다. 삭제/prune은 수행하지 않았다. 과거 이미지 참조 두 개의 조회 제한은 logitrack-preservation.md에 기록했다.

이 검증은 로컬 모의 평가 범위다. 외부 모델·SSRF·실제 코드 샌드박스, 운영 OIDC/키 관리/TLS, 백업 복원·리전·보존 정책, 실제 청구, CI 배포 게이트·원격 Actions는 이후 검증 대상이다.


## v0.34 추가 검증

전체 120개 테스트와 문법 검사가 통과했다. 성공 로그인 한도의 로그아웃/API 재시작 후 유지, 조직 격리, 서로 다른 API 인증 객체 간 동시 한도와 잠금 대기 후 철회/인증 대상 변경 거절을 검증했다. 실제 Docker에서 100개 사례·2,000개 규칙 평가와 신뢰 공개 키 기반 서명 검증이 통과했다. 실제 브라우저에서 사례 10개씩 표시, 다음 페이지, bounded-99 검색, 실패 필터의 빈 결과와 전체 100개/통과 2,000개 요약 유지를 확인했다. [검색 화면](evidence/bounded-evidence-search.jpg)은 이 합성 실행의 근거다.


## v0.35 추가 검증

전체 123개 테스트가 통과했다. 실제 CI 키 행 잠금 대기 중 만료·철회·발급자 권한 상실/비활성화, 만료 후 멱등 승인 재사용 거절, 별도 관리자 검토자의 권한 변경에 따른 차단을 검증했다. Docker API에서도 임시 키를 잠그고 만료를 기다린 뒤 재전송이 401이며 원래 서명 기록이 그대로 유지되고 중복 기록이 없음을 확인했다. 임시 키는 검증 후 철회했다. 새로운 평가를 기준으로 정상 CI 승인/서명 검증과 관리자 승인·반려 시나리오도 통과했다. 오래된 smoke 기준 실행을 이용한 게이트는 정상적으로 유효 시간 초과에 따라 차단했다.


## v0.36 추가 검증

전체 124개 테스트와 문법 검사가 통과했다. 저장된 PASS와 규칙 근거가 모순인 경우 관리자 승인은 409이며 기록을 만들지 않고, 반려 기록은 허용한다. Docker의 정상 관리자 승인·반려 smoke가 통과했다. 2026-10-03 22:56 UTC에 최신 데이터를 암호화 백업하고 새로운 격리 DB로 복원해 데이터·보안 카탈로그 지문, 모든 조직 RLS와 인증 테이블 격리를 확인했다. 복원 DB의 API/워커 CONNECT는 차단 상태로 보존했다. 비공개 백업·키·복원 보고서는 .local에 보관하며 저장소에 포함하지 않는다.


## v0.37 추가 검증

전체 127개 테스트가 통과했다. 3,000개 스키마 오류가 규칙 20개에 반복되는 합성 입력의 실패 판정을 보존하며 설명을 제한했고, JSON 노드가 적어도 UTF-8 결과가 8 MiB를 넘으면 전달/저장 검증에서 거절했다. 긴 이모지 속성 이름의 오류 설명도 절단 후 올바른 유니코드·JSONB 값으로 유지된다. Docker에서 같은 입력이 실패 20개·차단이며 전체 API 결과 52,908바이트와 신뢰 공개 키로 검증한 서명 차단 기록을 확인했다. 실제 화면에서도 오류 개수와 첫 5개 설명을 확인했다.


## v0.39 추가 검증

전체 133개 테스트가 통과했다. 검토 이력의 시계 역행·페이지 사이 삽입·조직/프로젝트/실행 커서 격리와 bigint 정밀도를 검증했다. 실제 Docker에서는 합성 반려 52개를 25·25·2개 페이지로 조회하고 기존 무쿼리 배열 50개 응답을 확인했다. 서명된 최종 게이트는 반려로 차단된다. 실제 브라우저에서도 25→50→52개와 마지막 페이지 버튼 비활성화를 확인했다. 만료된 로컬 세션으로 로그인 화면 전환 후 기존 계정의 정상 재로그인·입력 지움을 확인했다.
