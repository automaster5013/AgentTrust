# 에이전트·데이터셋 통합 카탈로그

4310 `/v1/catalog`의 등록 버전 탐색 중 에이전트·데이터셋을 4320의 현재 프로젝트 권한으로 함께 조회하는 범위다. `GET /api/catalog` → 인증된 Gateway → BFF `/backend/catalog` → 캠페인 영역의 통합 카탈로그로 연결한다. viewer도 조회할 수 있으며 쓰기 경로는 없다.

기존 `VersionHistoryReader`의 조직·프로젝트 SQL 조건과 RLS 트랜잭션을 그대로 사용한다. 각 종류의 최신 **25개**만 반환하며 시간·ID 내림차순, 불변 버전 좌표와 해시, 다음 이력 존재 여부를 전달한다. 종류별 조회는 각각의 읽기 트랜잭션이며 두 목록의 동일 시점 스냅샷을 보장하지 않는다. 목록 중 하나가 실패하면 부분 성공 응답을 만들지 않는다.

화면의 종류·이름 필터는 조회한 최대 50개 안에서만 작동한다. 상세는 기존 버전 API에서 다시 읽어 조직·프로젝트, ID·이름·버전·정확한 생성 시각, 내용 SHA-256을 확인한 뒤 공급자 또는 데이터셋 사례 수를 표시한다. 조회·필터 변경·오류 시 이전 상세를 지우며 늦은 응답을 버린다. 오래된 버전은 기존 종류별 버전 이력에서 계속 탐색한다.

정책 카탈로그, 범용 데이터셋 업로드, 공급자 연결 설정, 프로젝트 생성·전환, 구성원 관리는 이 범위에 포함하지 않는다. `deploymentAuthority=false`이며 상세 확인은 활성 버전 선택·평가 실행·릴리스 승인이 아니다. DB 스키마·계정·인증 설정 변경이나 현재 서비스 배포는 수행하지 않는다.

Core의 읽기 결합·범위 검증·실패 처리와 HTTP 메서드, Gateway/BFF의 인증·GET 전용 경로, Console 계약 검증을 검사한다. 실제 후보 API와 브라우저 수용은 새 커밋의 CI 결과를 별도로 기록하며 소스 구현만으로 수용 완료를 주장하지 않는다.
