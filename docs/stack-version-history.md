# Immutable version history and selection

The recent version list remains limited to 50. The authenticated `GET /api/version-history/{agents|datasets}` and optional `/{84-character-cursor}` expose 25 scoped metadata entries, with one look-ahead row. Ordering is PostgreSQL `(created_at DESC, id DESC)`, preserving microseconds. The existing immutable registry capacity remains 200 entries per kind per project; this bounded query needs no new table or migration.

Cursor domains `AGS` and `DTS` bind the registry kind, authenticated organization/project, exact timestamp and UUID. Navigation is not an authority token. Foreign tenant, wrong kind, other navigation domain, malformed length/padding, impossible timestamp and sub-microsecond boundaries fail closed. Gateway quota and BFF allow only the fixed GET paths and reject arbitrary query selection.

The browser validates the entire page schema, scope, kind, order, duplicate identifiers, requested boundary and exact last-row next boundary. The two history regions load manually with cancellation and a ten-second deadline. Selection separately retrieves the existing immutable version endpoint, verifies organization/project and SHA-256 of its canonical definition, matches identifier/key/version/hash to the displayed entry, and only then updates the controlled campaign selection. A historical option remains available even if absent from the latest 50. Selection creates no campaign, model call, provider reservation or approval. Existing Java admission still enforces compatible execution contracts and frozen profile bindings when a campaign is actually created.

Local validation on 2026-10-11: Java 79 tests, Gateway 21 tests, TypeScript 55 tests and the three changed runtime image builds passed. Actual OIDC read-only smoke compared all 70 agent entries over three pages and 79 dataset entries over four pages with independent scoped PostgreSQL order, tested viewer continuation, foreign-tenant/kind rejection and oldest/newest actual byte-hash verification. All 15 business tables remained unchanged and owned sessions logged out. One actual browser test selected a previous page version after real detail retrieval/hash verification and refused an injected wrong-kind page. No new synthetic business fixtures were needed.
