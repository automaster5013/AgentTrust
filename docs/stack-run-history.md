# 프로젝트 평가 이력

현재 조직·프로젝트의 평가를 Next.js 콘솔의 **프로젝트 평가 이력**에서 탐색한다. 최신 이력 조회, 다음·이전 페이지와 기존 평가 근거 열기를 제공한다. 한 페이지는 25개이고 브라우저의 탐색 경계 보관은 100페이지까지 제한한다. 최근 평가 목록과 기존 API는 유지한다.

`GET /api/run-history`와 `GET /api/run-history/{cursor}`는 WebFlux 인증·Redis 한도와 Java의 조직/프로젝트 RLS를 통과한다. 쓰기 메서드와 임의 쿼리 인자를 허용하지 않는다. 각 응답은 실제 저장된 평가의 공급자·시나리오·현재 결과·승인 필요 여부와 생성 시간을 반환한다. 모델 출력이나 근거 원문을 목록에 포함하지 않는다.

PostgreSQL의 `created_at DESC, id DESC` 순서와 마지막 행을 기준으로 다음 페이지를 찾는다. 시간의 마이크로초와 UUID를 정확히 보존하고, 응답에 26번째 행이 있을 때만 다음 경계를 발급한다. 경계는 `RUN` 구분 값과 조직·프로젝트·시간·ID의 63바이트를 base64url 84자로 표현한다. 감사 페이지의 경계와 구분하며, 잘못된 시간·다른 조직·프로젝트의 경계는 거부한다. 경계는 인증 토큰이나 서명 증거가 아니다.

브라우저는 실제 응답의 범위·최대 행 수·순서·중복·상태/판정 일관성과 마지막 행에 결합된 다음 경계를 검증한 후 표시한다. 전체 목록의 일관된 스냅샷을 제공하지 않으며 대기 평가의 결과는 조회 사이에 변할 수 있다. 새로운 평가는 최신 이력 조회로 확인하고, 릴리스 여부는 해당 평가의 현재 게이트에서 다시 확인한다.

`scripts/stack-run-history-smoke.py`는 기존 평가만 읽으며 처음 최대 3페이지를 PostgreSQL의 동일 범위 순서와 대조하고 TypeScript 검증기를 실행한다. 조회자·다른 조직·경계 형식·쓰기 거부도 실제 OIDC/BFF 경로에서 검사한다. 로컬 75개 평가 대조와 실제 브라우저의 페이지 이동·기존 근거 열기 검증이 통과했다. Java·게이트웨이·TypeScript 경계 테스트와 Docker 빌드도 통과했으며, 원격 CI는 각 커밋의 GitHub Actions 결과에서 별도 확인한다.

평가 근거를 선택하면 상세와 현재 OPA 게이트를 모두 확인한 뒤 표시한다. 두 조회에는 같은 10초 제한을 적용하고, 이전 근거·보관 해시·유사 조회는 먼저 비운다. 상세나 게이트가 멈추거나 실패하면 부분 결과를 릴리스 판단 근거로 표시하지 않는다. 같은 평가를 다시 선택해 재조회할 수 있다.

MinIO 보관 근거 확인과 pgvector 유사 근거 조회에도 각 요청의 10초 제한을 적용한다. 오류·시간 초과 후 버튼은 다시 사용할 수 있으며 자동 재시도 대신 사용자가 재조회한다. 조회를 시작할 때 이전 보관본 또는 유사 결과를 비우고 늦게 도착한 실패 요청의 결과를 표시하지 않는다.
