# Go 이미지 빌드의 모듈 다운로드 전송

격리 CI의 Collector 생성과 Loki 컴파일에서 서로 다른 공개 Go 모듈 다운로드가 HTTP/2 `INTERNAL_ERROR`로 중단됐다. 모듈의 코드·체크섬 불일치나 제품 기능 실패로 판정하지 않는다. 실패한 실행은 그대로 보존하며 완료된 전달 검증으로 표시하지 않는다.

Go를 사용하는 여덟 서비스 이미지의 컴파일 단계에만 `GODEBUG=http2client=0`을 설정한다. 이는 [Go 공식 HTTP 문서](https://pkg.go.dev/net/http#hdr-HTTP_2)에 정의된 클라이언트 HTTP/2 비활성화 설정이다. HTTPS 다운로드는 HTTP/1.1을 사용하고, 기존 TLS 인증서·호스트 이름 및 Go 모듈 체크섬 검증은 유지한다. `GOSUMDB=off`, 비보안 프록시, 체크섬 예외나 새로운 의존성 버전을 추가하지 않는다.

별도 `FROM`으로 시작하는 최종 이미지에는 이 환경 변수를 추가하지 않는다. 실행 서비스의 HTTP 프로토콜·인증·할당량 정책과 기존 Go 버전 및 소스 digest를 변경하지 않는다. 로컬의 실행 중인 인프라 이미지를 교체해서 CI 네트워크 문제를 수정하지 않는다.

고정 Go 이미지의 별도 제한된 검사에서 공개 모듈 프록시의 실제 HTTP/1.1·인증된 TLS 응답과 신뢰하지 않는 TLS 인증서 거부, 실제 모듈 다운로드 및 변조한 `go.sum` 거부를 대조한다. 전체 새 이미지 빌드·실제 레지스트리 실행·보안·서명 결과는 수정 revision의 CI와 전달 근거가 모두 완료된 뒤에만 확인한다.
