## 과거 새 스택 시연 계획 — 현재 제출에서 제외

이 절은 과거 `4320`의 Next.js·Java·Python 시연 계획을 보존한 기록이며 현재 제출 대상이 아니다. 최종 시연은 이 문서 상단의 기존 4310 순서와 [제출 후보 상태](portfolio-submission.md)의 고정된 네 종료 조건을 따른다. 계정·비밀 파일·원시로그를 영상에 노출하지 않는다.

권장 시연 순서는 다음과 같다.

1. 조직·프로젝트·역할을 확인하고 조회자와 관리자 권한의 차이를 설명한다.
2. 평가 결과의 규칙과 근거를 열고 평가 통과가 릴리스 허용을 뜻하지 않음을 설명한다. ID 직접 조회는 PR10/11의 승인된 적용 이후에만 실제 적용 기능으로 소개한다.
3. 현재 게이트와 승인·반려, 후보와 기준의 불변 비교 조건을 설명한다. 과거 서명과 현재 권한을 구분한다.
4. 보관본 바이트 검증·서명 검증·감사 이력의 확인 경로를 보여준다. 기존 신뢰키를 공개 자료에 포함하지 않으며 공개 가능한 샘플만 사용한다.
5. 실제 로컬 추론과 합성 시나리오의 차이, 현재 필터 범위·내보내기 한도·운영 미검증을 설명한다.

시연 녹화·사용자 과업·최종 로컬 수용은 아직 완료로 기록하지 않는다. 신규 평가나 승인/반려를 생성하는 시연은 기존 업무 데이터 보존 조건에 맞는 별도 검토 경로를 확보한 뒤 수행한다.

## Docker 없이 먼저 살펴보기

Node.js 24와 의존성 설치 후 `npm.cmd run demo:offline`으로 공개 합성 사례의 다섯 판정과 기록 응답의 회귀·누락 비교를 확인한다. 접근 키·Docker·업무 데이터 저장 없이 동작한다. `node scripts/portfolio-offline.mjs --json`은 자동화용 JSON을 출력한다. 시연 통과는 실제 관리자 승인·서명·배포 허용이 아니다. [처음 보는 사람을 위한 안내](reviewer-guide.md)에 전체 확인 순서를 기록했다.

## 준비와 실행

Node.js 24와 Docker Desktop을 준비하고 저장소 루트에서 실행한다. 기존 설치는 setup이 보존하는 접근 키·서명 키와 DB를 사용한다. `.env`와 `.local`은 공개하거나 업로드하지 않는다.

```powershell
npm.cmd ci --cache .cache/npm --ignore-scripts
npm.cmd run setup
npm.cmd run docker:up
npm.cmd run demo:preflight
npm.cmd run demo:portfolio
```

Linux에서는 `npm.cmd` 대신 `npm`을 사용한다. 기본 API는 `http://127.0.0.1:4310`이며 PORT 설정만 지원한다. 외부 주소는 받지 않으며 `--compare`, `--export-receipts`, `--organization-index 0..99`를 각각 한 번 선택적으로 받는다. 조직 인덱스는 기존 로컬 자격증명의 항목을 선택하며 기본값은 0이다. 없는 항목이나 잘못된 인자는 요청 전에 거절한다. 로그인한 관리자 조직·프로젝트가 선택한 범위와 다르면 평가 생성 전에 중단하고 자체 세션을 종료한다. seeded 프로젝트의 합성 데이터셋과 모의 에이전트, 기본 정책이 필요하다. 실제 작업 루트는 `C:\AgentTrust`다. LogiTrack 리소스는 변경하지 않는다.

첫 조직의 보관 한도가 가까우면 기존 두 번째 조직에서 기본 또는 비교 시연을 수행할 수 있다. 실행·키·과거 근거를 삭제하거나 한도를 늘리지 않는다.

```powershell
npm.cmd run demo:portfolio -- --organization-index 1
npm.cmd run demo:portfolio -- --compare --organization-index 1 --export-receipts
```

이 옵션은 시연 대상 선택이며 용량 예약이나 새 조직 생성을 뜻하지 않는다. 역할 시연도 `npm.cmd run demo:roles -- --organization-index 1`로 선택한다. 선택 조직의 관리자·작성자·조회자와 다른 기존 조직의 조회자로 경계를 검증한다. 기본 선택 0의 외부 조직은 1, 다른 선택의 외부 조직은 0이다. 조직·프로젝트가 다른지와 네 로그인 범위를 확인하고, 실패하면 생성 전에 중단하여 자신이 만든 세션을 종료한다.

감사 자료도 같은 기존 조직을 선택할 수 있다. 자식 비교 시연의 관리자 범위와 결과 자료의 조직·프로젝트, 조회자 세션을 대조한다. 선택 옵션만 추가한 기본 명령은 기존 여섯 영수증 형식을 유지하며 원래 의견과 HTML은 각각 명시적 옵션으로 추가한다.

```powershell
npm.cmd run demo:evidence -- --organization-index 1
npm.cmd run demo:evidence -- --organization-index 1 --with-reviews --with-report
```

각 시연은 로그인 범위 확인 후 조직 전체 용량을 사전 검사한다. 기본 시연 4개·비교 및 감사 자료 시연 6개·역할 시연 1개의 보관 공간과 동시 슬롯 최소 하나가 필요하다. 잘못된 범위·수치·한도, 공간 부족 또는 슬롯 없음에서는 정책·평가 생성 전에 중단하고 자체 세션을 종료한다. 이는 관측값이며 요청 시 서버의 기존 원자적 한도를 다시 확인한다. 비교 시연은 고정된 여섯 새 실행을 계획하며 실패 시 실제 생성 수는 더 적을 수 있다. 기본·비교·역할 시연의 비공개 보고서와 요약의 `capacityPreflightStatus`에서 검사 결과를 확인한다. 감사 자료의 자식 비교 시연도 별도 비공개 보고서에 결과를 남긴다. API가 이 관측을 제공하는 v0.139 이상이어야 한다.

v0.131부터 같은 내용의 불변 시연 승인 정책을 재사용한다. 카탈로그의 본문 해시가 일치할 때 원본 버전을 다시 읽어 ID·종류·본문 해시를 확인한다. 같은 이름의 더 약한 정책이나 조회 실패를 재사용으로 간주하지 않는다. 일치하는 버전이 없으면 한 번 생성하고 저장된 원본까지 확인한다. 평가 실행과 승인·반려는 매번 새로 생성하며 이전 실행의 승인을 재사용하지 않는다. 기존 버전·평가·검토 기록은 삭제하지 않는다.

## 확인할 흐름

| 단계 | 평가 결과 | 최종 게이트 | 시연할 의미 |
|---|---|---|---|
| 정상 응답 | pass | 허용 | 고정된 버전과 완전한 근거가 기준을 충족 |
| 업무 회귀 | block | 차단 | 필수 규칙 실패는 릴리스 불가 |
| 증거 누락 | inconclusive | 차단 | 판단 불가를 통과로 처리하지 않음 |
| 관리자 검토 정책의 정상 응답 | pass | 승인 대기·차단 | 평가 통과와 관리자 승인은 별도 |
| 관리자 승인 후 | pass | 허용 | 현재 유효한 승인과 근거를 함께 검사 |
| 관리자 반려 후 | pass | 차단 | 과거 통과 기록이 현재 배포 권한이 되지 않음 |

명령은 평가 4개, 최종 게이트 확인 6개를 실행하고 모든 게이트 기록의 Ed25519 서명을 로컬 신뢰 공개키로 검증한다. 단계별 JSON에는 실행 ID·판정·검증 기록 ID가 포함된다. 마지막 출력의 `status: passed`와 프로세스 종료 코드 0을 함께 확인한다. 실패하면 `blocked`, 종료 코드 1이며 원문 오류나 접근 키를 출력하지 않는다.

## 기준 실행 비교까지 자동으로 준비하기 — v0.113

```powershell
npm.cmd run demo:portfolio -- --compare
```

기본 시연과 같은 합성 사례에 두 기준 실행을 추가한다. 기본 정책과 관리자 정책별로 서로 다른 정상 응답 기준을 만들고, 후보 4개·기준 2개 평가와 최종 게이트 6개의 총 12단계를 수행한다. 정상 비교는 통과, 업무 회귀는 회귀 규칙 포함 차단, 근거 누락은 비교 미완료·차단이다. 관리자 사례는 비교가 통과해도 승인 대기·반려이면 차단되고 승인 후에만 허용된다.

출력의 각 게이트에는 후보 `runId`, 정책에 맞는 `baselineRunId`, 비교 가능 여부·통과 여부·회귀 수가 포함된다. 후보의 고정 버전과 후보·기준의 실행·스냅샷·결과 해시를 원본 artifact와 대조하고 로컬 신뢰 공개키로 서명을 검증한다. 마지막 출력의 `withBaselineComparison: true`, `steps: 12`, `status: passed`와 종료 코드 0을 함께 확인한다. 추가 인자·중복 옵션은 인증 전에 거절한다. 실패 정리와 자체 세션 종료는 기본 시연과 같으며 기존 기록을 삭제하지 않는다.

화면에서 출력한 후보 UUID를 조회하고 ‘기준 실행과의 회귀 비교 포함’을 선택한 뒤 해당 게이트의 `baselineRunId`를 입력하면 같은 비교를 새로 확인할 수 있다. 결과 유효 시간 600초가 지나면 명령을 다시 실행한다. 자동 시연은 관리자 사례를 반려로 끝내므로 승인 대기·승인 시점의 과거 서명 기록과 현재 반려를 구분한다.

## 화면 시연

1. 로컬 화면에 관리자 접근 키로 로그인한다. 키는 `.local/credentials.json`에서 로컬로 확인한다.
2. 기본 프로젝트의 실행 기록에서 ‘실행 ID로 바로 조회’에 명령이 출력한 실행 UUID를 붙여 넣고 ‘실행 ID 조회’를 누른다. 조회 완료 뒤 탐색 메뉴의 평가 근거로 이동해 스냅샷과 사례별 근거, 필수 규칙의 결과를 설명한다.
3. 탐색 메뉴의 최종 게이트로 이동해 새 검증을 요청한다. 화면의 확인 시각·검증 기록 ID와 CI 릴리스 검증 기록을 함께 확인한다. ‘이번 검증 기록 JSON 저장’으로 해당 artifact·해시·서명을 바로 내보낼 수 있다.
4. 관리자 검토 사례를 선택한 뒤 탐색 메뉴의 릴리스 검토에서 승인·반려 이력을 확인한다. 시연 명령 종료 후 이 사례는 반려 상태다. 과거 승인 시점의 통과 기록과 현재 차단을 비교한다.
5. 필요하면 새 합성 실행을 만들고 직접 승인한 뒤 최종 게이트를 확인한다. 실제 배포는 수행하지 않는다.

## 8분 발표 구성

아래 시간은 권장 발표 배분이며 측정된 성능이나 실제 데모 실행 시간이 아니다. 데모 명령과 화면 로그인은 발표 전에 준비한다. 결과가 기본 유효 시간 600초를 넘었다면 새 평가와 게이트를 실행한다.

| 시간 | 보여줄 내용 | 확인할 근거 |
|---|---|---|
| 0–1분 | 기업 개발팀의 변경 평가와 릴리스 승인 문제 | 고정 버전·근거·별도 최종 게이트 |
| 1–3분 | 정상 응답과 업무 회귀 비교 | 같은 데이터셋·정책의 후보와 기준, 변경/회귀 규칙 수 |
| 3–4분 | 회귀 규칙 링크로 정확한 사례 이동 | 선택한 사례와 전체 사례 수, 원문 출력·필수 규칙 실패 |
| 4–6분 | 관리자 정책의 비교 통과와 승인 대기·승인·반려 | 비교 판정과 최종 판단 분리, 최신 검토 이력 |
| 6–7분 | 원본 기록 저장과 신뢰 공개키 검증 | JSON은 과거 확인 기록, 서명 검증은 현재 배포 권한이 아님 |
| 7–8분 | CI의 테스트·후보 digest·독립 실행·승격 | [고정 검증 기준선](portfolio-engineering.md), 미완료 고객 연동·실제 서버 배포 |

기준은 최근 완료 목록에서 선택하거나 UUID로 입력한다. 후보 자신은 기준으로 지정할 수 없으며 목록은 호환성 검증 결과가 아니다. 관리자 정책 비교를 시연할 때에는 기준·후보 모두 같은 정책 내용을 사용한다. 반려로 끝나는 자동 데모의 관리자 사례를 그대로 사용하면 ‘승인 대기’ 대신 ‘반려’가 보인다. 승인 대기를 보여주려면 새 합성 실행을 생성한다.

회귀 링크를 누르면 기존 검색·필터를 해제하고 정확한 사례만 표시한다. ‘선택 사례 해제’로 전체 근거에 돌아오고 전체 결과 JSON의 사례 수가 유지되는 것을 설명한다. 기준 ID를 바꾸면 이전 판단·저장 버튼·회귀 링크가 무효화되는 모습도 확인할 수 있다.

## 기록과 제한

매 실행은 평가·검토·감사·게이트 기록을 추가한다. 관리자 검토 정책은 내용 해시가 일치하는 기존 불변 버전을 재사용하며 없는 경우에만 새 버전 하나를 등록한다. 기존 기록을 삭제하거나 덮어쓰지 않는다. 보고서는 `.local/portfolio-demo-<UUID>.json`에 독점 생성되며 합성 실행의 요약만 보관한다. 보고서 자체는 서명된 릴리스 증명이 아니며 기록 원본은 화면/API에서 조회한다. 설치된 버전이 아닌 브랜치에서 실행하는 경우 API·워커 이미지를 먼저 다시 빌드한다.

실패 시 ID를 확인한 미완료 실행을 취소하고, 승인을 시도한 사례에 반려를 추가하며 자체 로그인 세션을 종료한다. 통신 중단으로 서버가 요청을 처리했는지 알 수 없는 경우 모든 생성 기록을 발견한다고 보장하지 않는다. 정리 실패는 성공으로 처리하지 않는다. 관리자 자격증명으로 수행한 합성 시연은 실제 사람의 검토, 역할 분리, 고객 파일럿을 증명하지 않는다. 최종 게이트는 확인 시점의 판단이며 실제 배포 직전에 CI에서 다시 확인해야 한다.

## 권한과 조직 경계 시연

```powershell
npm.cmd run demo:roles
```

기존 seeded 조직의 접근 키를 로컬에서 사용한다. 기본 선택은 첫 조직의 관리자·작성자·조회자와 두 번째 조직의 조회자로 자체 세션 4개를 만든다. `--organization-index 1`은 두 조직의 시연 역할을 바꾼다. 새 접근 키나 권한은 발급하지 않는다.

| 주체 | 검증하는 행동 | 예상 결과 |
|---|---|---|
| 작성자 | 합성 평가 생성 | 완료·평가 pass, 관리자 승인 대기 |
| 조회자 | 실행 근거와 고정 스냅샷 조회 | 200 |
| 조회자 | 평가 생성 | 403 |
| 작성자 | 정책 등록 | 403 |
| 작성자·조회자 | 관리자 승인 작성 | 각각 403, 검토 기록이 생기지 않음 |
| 다른 조직의 조회자 | 실행 조회·최종 게이트 확인 | 각각 404 |
| 관리자 | 승인·반려 기록 | 승인 후 허용, 반려 후 차단 |
| 조회자 | 승인 대기·승인·반려의 최종 게이트 | 세 판단과 서명 검증 확인 |

명령은 정책 1개·평가 1개와 검토·게이트 기록을 보존한다. 단계 11개 중 거절 검증은 6개이며 최종 게이트 서명은 3개다. 보고서는 `.local/portfolio-roles-<UUID>.json`에 독점 저장한다. 종료 코드 0과 `status: passed`, `cleanupSucceeded: true`, `sessionsLoggedOut: true`를 함께 확인한다. 권한 거절 대신 허용되거나 서명·정리가 실패하면 종료 코드 1이다. 자체 미완료 실행을 작성자로 취소하고, 승인 시도 후 실패한 사례를 관리자로 반려하며 생성한 세션을 각각 종료한다. 통신 중단의 기록 발견 제한은 앞 절과 같다.

화면에서는 역할별로 별도 브라우저 세션을 사용해 작성자의 실행 버튼, 조회자의 비활성 실행 버튼·읽기 가능한 근거, 관리자의 검토 양식을 확인할 수 있다. 이 명령은 기존 RBAC와 조직 격리를 실제 API에서 시연하며, 정책상 2인 승인이나 실사용자 역할 분리를 추가하지 않는다.

## 시연 준비 상태 점검

`npm run demo:preflight`는 데이터·정책·세션·보고서 파일을 만들지 않는 읽기 전용 검사다. Node.js 24와 PORT, 로컬 설정/두 조직의 역할 키 형식, Ed25519 키 쌍, 현재 Compose API·DB·워커 실행 상태와 API loopback 포트, 공개 health 응답의 DB 연결을 순서대로 확인한다. 첫 실패 단계 이후는 not_run으로 표시한다. status passed와 종료 코드 0, 또는 blocked와 종료 코드 1을 반환하며 고정 안내만 출력한다. 키·Docker 원문·오류 스택은 출력하지 않는다.

Docker가 꺼져 있거나 서비스가 멈췄다면 안내에 따라 Docker Desktop과 docker:up을 실행한다. 설정/키 단계가 막히면 기존 비밀 파일을 보존하고 setup 상태를 확인한다. 명령은 시작·재시작·마이그레이션·로그인·외부 연결을 수행하지 않는다. 성공은 구조와 현재 가용성의 점검이며 키의 DB 인증 유효성·seed 버전 내용·워커 실제 평가 성공·현재 이미지의 소스 일치를 증명하지 않는다. 이어서 두 데모 명령으로 실제 평가·권한·서명을 확인한다. 운영 배포 전 검사는 별도의 deploy:preflight를 따른다.

실행 ID 조회는 현재 로그인한 조직·프로젝트 권한을 그대로 적용한다. 다른 프로젝트의 실행이면 현재 프로젝트 선택을 먼저 확인한다. 없는 실행과 접근할 수 없는 실행은 상세 존재 정보를 구분해 표시하지 않는다. 목록 필터와 페이지는 유지되며 잘못된 ID를 확인하는 동안 기존 선택도 유지된다. 다른 실행 선택·프로젝트 전환·로그아웃 후 도착한 조회 응답은 선택을 바꾸지 않는다.

현재 검증 기록의 JSON은 별도 신뢰 공개키로 receipt:verify를 실행할 수 있는 기존 형식이다. [서명 운영 안내](receipt-signatures.md)를 따른다. 브라우저 다운로드는 과거 확인 기록이며 실제 배포 전에 새 게이트를 요청한다. 재검증·검토 새로고침·실행 전환 후에는 이전 다운로드가 비활성화된다. 이력에서 과거 기록을 다시 저장하는 기능은 계속 제공된다.

최종 게이트의 ‘기준 실행과의 회귀 비교 포함’을 선택하고 완료된 기준 실행 UUID를 입력하면 서버의 회귀 판단을 함께 확인한다. 같은 프로젝트 및 데이터셋·정책 내용이 필요하다. 기본값은 비교 제외이며 후보 자신은 기준으로 선택할 수 없다. 옵션·ID 변경 후 다시 확인해야 한다. 저장 파일은 선택한 기준의 원본 서명 근거를 포함한다.

## 기존 설치 재시연 기준선 — v0.82

2026-10-04의 기존 Windows 설치에서 안내한 npm ci와 setup을 다시 실행했다. .env, 역할 접근 키 파일과 서명 private/public 키 네 파일의 바이트 지문이 모두 유지됐다. 준비 5단계, 평가·승인 10단계, 권한 11단계가 통과했고 자체 세션을 종료했다. 브라우저에서도 관리자 검토 사례를 UUID로 조회한 뒤 새 최종 게이트가 반려를 이유로 차단하는 것을 확인했다. 원본 기록과 화면은 private .local에 보관한다.

이는 기존 설정의 재사용 검증이다. 로컬의 새 볼륨 설치나 다른 사용자 PC 설치는 수행하지 않았다. GitHub CI의 새 runner에서는 setup부터 별도 후보 이미지 실행·승격까지 검증하며 고정 커밋 근거는 기술 설명 문서에서 확인한다. 반복 시연은 합성 정책·실행·감사 기록을 추가하므로 기존 기록을 보존하면서 필요한 횟수만 실행한다.

## 시연 영수증과 실행 결합 — v0.114

기본·기준 비교·역할 시연 모두 Ed25519 서명 검증 뒤 서명된 요청과 결과를 실제 요청 및 화면에 표시하는 응답과 대조한다. 후보 실행 ID·스냅샷 해시·결과 해시가 방금 완료한 실행과 일치해야 한다. 요청하지 않은 기준 근거, 다른 실행의 유효한 서명, 서명 범위 밖에서 바뀐 승인·판정은 시연 성공으로 처리하지 않는다. 공개키는 1 KiB 이하의 정규 UTF-8 Ed25519 SPKI 파일로 검증한 후 로그인한다. 이 검사는 합성 시연의 신뢰성을 보완하며 실제 배포 허가를 대신하지 않는다.

## 과거 검증 기록에서 평가 근거로 이동 — v0.115

CI 릴리스 검증 기록의 전체 기록 UUID를 확인하고 ‘후보 평가 근거 보기’를 누르면 현재 조직·프로젝트 권한으로 해당 실행을 다시 조회한다. 기준 비교가 있는 기록은 ‘기준 평가 근거 보기’도 제공한다. 목록을 여러 페이지 거슬러 찾거나 실행 UUID를 복사해 다시 입력하지 않아도 근거를 열 수 있다. 기록의 과거 통과 판정은 현재 최종 게이트에 복원하지 않는다. 이동한 실행의 릴리스 허용 여부는 새 최종 게이트 요청으로 확인한다.

잘못된 UUID·접근 불가·다른 실행의 응답은 기존 근거 선택을 유지한다. 중복 이동을 억제하며 조회 중 다른 실행 선택·프로젝트 전환·로그아웃이 일어나면 이전 응답을 표시하지 않는다. 이 기능은 평가 근거 조회이며 서명 검증이나 배포를 수행하지 않는다.

## 서명 근거 묶음 저장과 오프라인 검증 — v0.116

```powershell
npm.cmd run demo:evidence
# 기본 흐름만 묶음으로 저장하려면
npm.cmd run demo:portfolio -- --export-receipts
# 기록된 directory와 manifestSha256를 별도 검토에 사용
npm.cmd run demo:evidence:verify -- .local/portfolio-evidence-<UUID> .local/receipt-signing/public.pem <manifestSha256>
```

`demo:evidence`는 기준 비교 시연을 완료하고 자체 세션을 종료한 뒤 여섯 영수증과 목록을 새 `.local/portfolio-evidence-<UUID>` 폴더에 저장한다. 실제 별도 CLI 프로세스가 지정 공개키·출력된 목록 SHA-256으로 파일 여섯 개의 해시·Ed25519 서명·조직/프로젝트·실행 결합·통과/차단·승인 전후 순서를 검증한다. 기본 흐름은 `--export-receipts`, 비교 흐름은 `--compare --export-receipts`로 저장할 수 있다. 묶음은 API에서 받은 서명 요청·판정·증거 해시를 보존하며 평가의 원문 입출력이나 접근 키·서명 비밀키를 포함하지 않는다.

검증기는 네트워크를 사용하지 않고 독립적으로 신뢰한 공개키 경로를 요구한다. 목록은 별도로 서명되지 않는다. 선택적으로 제공하는 **예상 목록 SHA-256은 검토자가 다른 신뢰 경로로 확보해야** 묶음의 구성까지 고정한다. 묶음 안의 값을 그대로 신뢰하면 구성의 독립적 인증이 아니다. 예상 해시를 생략하면 각 영수증의 서명과 일관성만 확인하며 출력의 `expectedManifestDigestMatched`는 false다. 저장 명령과 검증 명령을 같은 시연 프로세스에서 연결한 확인은 독립 검토자의 신뢰 설정을 증명하지 않는다.

파일명이 정해진 여섯 JSON과 목록만 허용하며 경로 이동·추가 파일·누락·잘못된 UTF-8·크기 초과·다른 키·변조·서명 유효하더라도 모순인 판정이나 승인 근거를 거절한다. 완료·실행 정리·로그아웃 실패 시 묶음을 발행하지 않는다. 목록은 마지막에 독점 생성한다. 디스크 오류로 생긴 미완성 폴더는 성공으로 처리하지 않으며 기존 파일을 덮어쓰지 않는다. 이것은 과거 서명 근거 검증이다. 현재 승인 유효성, 실제 고객 모델 실행, 상용 배포 권한을 확인하지 않는다.

## 합성 프로젝트와 생성 실행의 고정 — v0.117

기본·비교·묶음 시연은 로컬 설정에 기록된 합성 프로젝트를 요청 헤더로 명시한다. 로그인 뒤 역할·조직·프로젝트를 확인한 뒤 카탈로그나 생성 API를 사용한다. 역할 시연도 네 세션 각각의 지정 조직·프로젝트·역할을 확인한다. 설정 오류나 세션 범위 불일치는 시연을 차단하고 발급받은 자체 세션을 종료한다.

평가 완료 응답은 처음 생성한 실행 ID 및 에이전트·데이터셋·정책 버전과 일치해야 한다. 응답이 달라도 정리 대상은 처음 생성한 실행으로 유지하며 다른 실행을 취소하지 않는다. 기본·비교·역할 시연의 요청 결합과 실패 정리를 테스트했다. 원래 응답 ID를 받지 못한 통신 중단의 생성 여부까지 발견하는 기능은 아니다.

## 근거 기록 탐색과 검증 조기 종료 — v0.118

왼쪽 ‘검증 기록’ 탐색으로 기록 패널을 직접 연다. 판정·확인 시각·전체 기록 UUID와 후보/기준 이동·JSON 저장 버튼을 줄을 나눠 표시한다. 다른 실행을 선택하면 이전 기록에서 이동했다는 안내를 지워 현재 근거 선택과 혼동하지 않는다.

오프라인 묶음 판독은 목록의 키 ID를 먼저 지정 공개키와 확인하며, 파일을 하나씩 해시·서명 검증한 뒤 다음 파일을 읽는다. 서명이 틀린 첫 파일이나 다른 키의 목록이 있으면 나머지 본문을 파싱하지 않는다. 마지막에는 여섯 기록의 전체 시나리오 관계를 함께 검증한다. 파일당 바이트 제한과 전체 구성 제한은 유지한다.


## 과거 검증 기록 상세와 본문 해시 확인 — v0.119

‘검증 기록’의 ‘기록 상세 보기’에서 과거 판정·차단 사유·관리자 승인 상태·회귀 규칙·고정 버전·근거 해시를 확인한다. 기록과 현재 조직/프로젝트의 결합 및 실제 본문의 정규화 SHA-256을 확인한 뒤 표시한다. 과거 기록 조회는 현재 릴리스 허용을 복원하지 않는다. 서명 포함 여부와 별도 신뢰 공개키 CLI 검증을 구분한다.

최종 게이트와 과거 JSON 저장도 실제 본문 해시를 확인한다. 목록의 해시만 유지한 본문 변경과 잘못된 현재 게이트 해시를 변경 전 실패로 재현했다. 비동기 해시 확인 중 로그아웃·실행 선택 변경·상세 닫기·다른 기록 조회가 이전 응답을 되살리지 못한다. 본문 깊이/노드 제한과 객체 키 순서 호환성, 승인 만료와 비교 통과의 구분, 정확한 회귀 규칙 텍스트를 테스트한다.


## 검증 기록 조건 조회 — v0.120

‘검증 기록 판정’과 ‘검증 기록 후보 실행 UUID’를 입력하고 ‘기록 조건 적용’을 누르면 서버가 같은 조직/프로젝트의 기록만 좁혀 조회한다. 조건 입력 중에는 기존 적용 조건을 유지하며 이전 페이지도 적용 조건으로 조회한다. ‘조건 초기화’는 전체 기록으로 돌아간다. 일치하지 않는 후보는 빈 목록으로 표시하고 다른 조직의 존재 여부를 공개하지 않는다.

새 조건을 적용하면 이전 목록·페이지 커서·과거 상세를 지운다. 지연된 이전 조건 응답과 로그아웃 후 응답은 결과를 복원하지 않는다. 서버의 페이지 커서는 판정·정규화한 후보 UUID·기록 리소스에 묶여 다른 조건이나 CI 키 목록에서 재사용할 수 없다. 이전 버전의 검증 기록 커서를 이어 쓰려면 새로고침해야 한다.

`demo:evidence`는 오프라인 검증 뒤 자체 viewer 세션으로 원래 네 후보·통과/차단 조건의 페이지를 조회한다. 여섯 서명 artifact에서 확인한 ID·본문 해시·판정·후보/기준·확인 시각·서명 키와 목록 메타데이터를 대조하고 중복·누락·과대 커서를 거절한다. 목록에 전체 근거가 섞이지 않는지 확인하고 자체 세션을 종료한다. 이 단계는 과거 기록의 조회 정합성이며 현재 배포 권한 확인이 아니다.


## 연결된 과거 관리자 검토 근거 — v0.121

검증 기록 상세는 기록에 포함된 검토 ID·해시에 해당하는 원래 관리자 의견을 조회한다. 조직/프로젝트·후보 실행·스냅샷/결과 해시·검토 판정·시각과 실제 본문 해시를 결합한 뒤 텍스트로 표시한다. 나중에 반려가 추가되거나 검토자의 권한이 바뀌어도 과거 의견 조회는 현재 승인을 복원하지 않는다. 연결된 검토가 없거나 모순이면 확인된 검증 기록은 유지하며 별도 실패 안내를 표시한다. 서명 검증은 독립 공개키 CLI의 책임으로 유지한다.

서버는 검토 해시와 함께 저장 행의 ID·조직·프로젝트·실행·검토자·판정·시각을 대조한다. 올바른 해시를 가진 모순된 본문도 목록·상세·최종 게이트에서 503으로 차단하고 의견 원문을 오류에 포함하지 않는다. 이를 변경 전 실패로 재현했다. `demo:evidence`의 viewer 단계도 원래 승인·반려 의견 두 개를 조회해 서명 artifact에 포함된 ID·해시와 대조한다.

상세 닫기는 원래 버튼 또는 기록 패널로 키보드 포커스를 돌려준다. 검색 결과가 없는 경우는 전체 기록이 없는 경우와 안내를 구분한다. 로그아웃·닫기·조회 조건 초기화 뒤의 늦은 의견 응답이나 해시 계산이 이전 상세를 복원하지 않는다.

실제 v0.121 Docker 화면에서 이후 반려가 있는 실행의 원래 승인 의견과 반려 의견을 각각 조회했다. [원래 승인 근거](evidence/original-review-v121.png)와 [현재 반려 차단](evidence/current-rejection-v121.png)은 2026-10-05 08:43~08:45 KST의 합성 시연 화면이며 촬영 이후의 현재 상태를 보장하지 않는다. 상세 열기·닫기의 실제 키보드 포커스와 목록 갱신 후 패널로의 복귀도 확인했다.


## 원래 검토 의견을 포함한 오프라인 감사 자료 — v0.122

`npm.cmd run demo:evidence -- --with-reviews`는 기존 여섯 서명 기록과 연결된 승인·반려 의견 두 개를 새 schemaVersion 2 묶음으로 저장한다. 기본 명령과 기존 schemaVersion 1 묶음 검증은 유지한다. 새 묶음은 manifest.json, receipt-1.json~receipt-6.json, review-1.json~review-2.json의 정확한 아홉 일반 파일만 허용한다. 의견 본문과 목록은 각각 64 KiB, 영수증은 기존 제한을 적용하고 심볼릭 링크·추가/누락 파일·잘못된 UTF-8을 거절한다.

기존 데모의 정리와 로그아웃, 자체 viewer 세션의 원래 검토 조회와 로그아웃까지 성공한 뒤에만 의견을 포함한 묶음을 쓴다. 별도 오프라인 CLI는 독립 신뢰 공개키로 여섯 Ed25519 서명을 먼저 확인하고, 서명 artifact가 지정한 원래 검토 ID·해시·조직/프로젝트·후보 실행·평가 해시·판정·시각을 의견 본문과 결합한다. 파일/목록 체크섬을 다시 계산해도 서명된 참조와 다른 의견은 거절한다. 의견 파일의 해시 자체를 별도 서명으로 표현하지 않는다.

같은 `demo:evidence:verify` 명령으로 검증하며 새 형식은 `reviewBodiesVerifiedOffline: true`, `linkedReviewsVerified: 2`를 반환한다. 목록 SHA-256 일치는 전달된 값과의 일치이며 별도 목록 서명이나 신뢰 경로의 증명이 아니다. 과거 의견과 영수증은 현재 승인·현재 관리자 권한·현재 배포 허용을 보장하지 않는다. 접근 키, 서명 비밀키, 평가 원문 입출력은 포함하지 않는다. 실제 의견은 기밀일 수 있으므로 내보낸 자료의 전달 대상은 운영자가 정한다.


## 조회 범위가 바뀐 과거 기록 다운로드 — v0.123

기록 JSON 저장은 버튼을 만든 로그인 범위와 원래 목록에 묶인다. 조건 적용·초기화·전체 새로고침이 시작되면 이전 목록의 진행 중 다운로드와 오류 안내를 무효화한다. 응답을 기다리는 동안뿐 아니라 본문 해시 확인 중에도 변경 여부를 확인한다. 이전 로그인/목록의 분리된 버튼은 요청을 보내지 않는다. 다음 페이지를 추가하는 동작은 기존 목록을 유지하므로 이미 요청한 다운로드도 유지한다. 조회 조건 초기화, 목록 교체 후 늦은 오류, 재로그인 후 이전 버튼 동작을 수정 전 실패로 재현했고 현재 다운로드와 페이지 추가 호환성도 검증했다.


## 읽기용 오프라인 감사 보고서 — v0.124

`npm.cmd run demo:evidence -- --with-reviews --with-report`는 여섯 서명 기록과 원래 검토 의견 두 개를 검증한 뒤 원본 묶음 밖의 새 `.local/portfolio-audit-<UUID>.html`을 생성한다. 기존 자료에서 보고서를 만들려면 [감사 보고서 안내](portfolio-audit.md)를 따른다. 보고서는 과거 판단·고정 버전·후보/기준·해시·원래 검토 의견을 표시하며 현재 배포 허용을 확인했다고 주장하지 않는다. HTML 자체는 별도 서명되지 않은 사본이므로 원본 묶음과 신뢰 공개키의 재검증이 필요하다.

의견·이유·ID는 HTML 텍스트로 이스케이프하고 스크립트·외부 자원 없는 문서로 만든다. 출처 서명/파일 검증이 실패하면 보고서를 만들지 않고 오류 입력을 출력하지 않는다. 기존 파일은 덮어쓰지 않으며 원본 폴더 또는 디렉터리 별칭을 통한 그 하위 경로도 출력 대상으로 거절한다. 기존/새 자료 형식·실제 서명 의견의 마크업·별도 CLI·기존 파일/원본 목록 보존·별칭 경계를 테스트하고 실제 로컬 API의 자료로 생성했다. 로컬 HTML URL의 브라우저 열기는 보안 정책이 차단했으므로 이 기록은 화면의 시각 검증을 완료했다고 주장하지 않는다.


## 기록 새로고침의 이전 목록 정리 — v0.125

전체 새로고침은 요청 시작 시 이전 행·페이지 커서·표시 개수·과거 상세를 정리한다. 실패하면 이전 목록의 비활성 버튼이나 낡은 상세를 현재 결과처럼 남기지 않는다. 연결된 검토 의견이 대기 중이었어도 이전 상세를 복원하지 않는다. 다음 페이지 추가는 기존 행을 유지하며 정상 다운로드와 페이지 조회를 계속 지원한다. 대기 중 새로고침 실패와 늦은 검토 의견을 수정 전 실패로 재현했고 재시도 후 새 목록의 다운로드도 확인했다.


## 선택 조직의 조회 측정 — v0.148

```powershell
npm.cmd run benchmark:metadata -- --organization-index 1 --samples 20 --concurrency 4
```

측정 도구는 기존 조직의 조회자 키·프로젝트를 선택하고 로그인 조직·프로젝트·역할을 확인한 뒤 고정된 identity/catalog/실행 요약/사용량 조회만 측정한다. 기본 선택은 0이며 없는 항목·중복·잘못된 인자는 인증 전에 거절한다. 비공개 보고서와 요약에 선택 인덱스·세션 범위 확인을 남기며 성공·실패 뒤 자체 세션을 종료한다. 네 동시 요청은 한 조회자 세션의 제한된 HTTP 파동이며 네 워커나 처리량 측정이 아니다. 실제 평가를 생성하지 않고 로그인·로그아웃 감사는 남긴다.


## 선택 조직의 제한된 병렬 평가 — v0.149

```powershell
npm.cmd run smoke:burst -- --organization-index 1 --runs 6
```

기존 조직의 작성자 키·프로젝트를 선택하고 조직·프로젝트·역할을 확인한 뒤 합성 평가를 생성한다. 기본 선택 0, 실행 수 기본 12개·범위 2~20개와 최대 네 진행 요청의 기존 제한을 유지한다. 잘못된 범위에서는 카탈로그 읽기·평가 생성 전에 중단하고 자체 세션을 종료한다. 완료 실행의 생성 감사·종료 감사·사용량 대조는 선택 조직과 프로젝트로 제한한다. 작성자에게 관리자 운영 용량 조회 권한을 부여하지 않으며, 실제 생성 시 서버의 원자적 한도가 적용된다. 이 도구는 합성 실행을 저장하며 워커 네 개나 상용 처리량을 뜻하지 않는다.
