# 캠페인 생성 응답이 불확실할 때의 복구

캠페인 생성은 여러 자식 평가를 함께 등록한다. 저장 후 응답이 끊겼다고 새 요청 키를 만들어 다시 실행하면 같은 조건의 캠페인이 중복 생성될 수 있다. Console은 제출할 에이전트·데이터셋 버전 ID와 내용 해시, 관리자 승인 필요 여부, 비교 기준과 근거 유효 기간을 생성자·조직·프로젝트 및 요청 키와 함께 변경할 수 없는 입력으로 보관한다.

생성 요청은 10초 제한과 UTF-8 1MiB 응답 제한을 적용한다. 네트워크·본문 지연·잘못된 JSON/UTF-8·응답 크기 초과·서버/게이트웨이 5xx는 저장 결과가 불확실한 상태다. 생성 응답 뒤의 불변 조건 조회가 실패한 경우에도 원래 요청을 유지한다. 최초 POST의 명확한 400/401/403/404/409/413/422/429 거부와 구분한다. 이미 결과가 불확실했던 요청은 후속 재제출의 거부만으로 폐기하지 않는다.

불확실한 상태에서는 새 캠페인 생성 버튼을 사용할 수 없다. 운영자는 두 경로 중 하나를 명시적으로 선택한다.

- **기존 캠페인 요청 조회**: 원래 요청 키로 소유한 등록을 읽고 캠페인 상세의 버전 ID·실제 내용 해시·승인 조건, 별도 불변 릴리스 조건의 비교 기준·유효 기간을 대조한다. 조회 자체는 생성·공급자 실행을 하지 않는다.
- **같은 캠페인 요청 다시 제출**: 원래 키와 원래 입력을 보낸다. 양식을 바꾸더라도 이 재제출의 조건은 바뀌지 않는다. 기존 멱등 등록이 이미 있으면 원래 캠페인을 반환한다. 아직 등록되지 않았다면 기존 권한·한도·버전 수명·비교 기준 검증을 적용한다.

`GET /api/campaign-requests/{key}`는 인증된 현재 조직·프로젝트·생성자와 키를 함께 조회한다. 같은 조직의 다른 생성자와 외부 조직, 존재하지 않는 키는 404다. 익명은 401이며 쓰기 메서드는 추가하지 않는다. 키는 기존 등록과 같은 ASCII 영숫자·밑줄·하이픈 8~100자로 제한한다. 응답의 `deploymentAuthority`는 false다. 키나 자격 증명은 검사 보고서에 기록하지 않는다.

등록 입력과 조건을 확인한 뒤 목록·현재 게이트 조회만 실패한 경우는 저장 결과가 불확실한 경우와 별도 안내한다. 검증된 캠페인 상세를 유지하되 이전 게이트는 지운다. 과거 입력 확인과 현재 배포 권한은 다르며, 현재 게이트의 필수 실패·근거 누락·만료·반려를 우회하지 않는다.

복구 입력은 현재 화면의 메모리에만 보관한다. 로컬 저장소·쿠키·서버 신규 테이블에 저장하지 않는다. 새로 고침·로그아웃·인증 범위 변경 뒤에도 유지되는 복구함은 구현하지 않았다. 원래 업무 데이터나 근거 보관본을 삭제해서 복구하지 않는다.

## 검증과 전달 범위

Java는 소유자·조직·프로젝트 결합, 잘못된 키의 조회 전 거부, 없는 요청의 쓰기 미실행과 모호한 결과 거부를 검사한다. Console은 입력 불변성·실제 내용 해시·비교 기준/유효 기간·포인터 범위 및 응답 크기·인코딩·취소를 검사한다. Gateway는 이 경로를 기존 인증·조직 할당량 보호에 포함하며 읽기 외 메서드와 임의 경로를 거부한다.

`scripts/stack-campaign-request-resolution-smoke.py`는 이미 존재하는 소유 등록만 읽으며 같은 조직의 다른 생성자·외부 조직·익명·잘못된 키·쓰기 메서드 거부와 자체 세션 종료를 확인한다. 브라우저 검사는 기존 합성 캠페인과 가로챈 생성/조회 응답으로 실제 10초 중단, 원래 키/본문 유지, 명시적 재제출, 조건 조회 실패 후 입력 보존, 올바른 조회 복구와 현재 게이트 실패의 구분을 확인한다. 로컬 실행에는 읽기 전용 네트워크 가드를 적용한다.

소스·레지스트리 CI에 읽기 전용 조회 검사와 안전한 진단 JSON 업로드를 포함한다. 원격 CI·게시 이미지·서명·오프라인 변조 검증의 완료 여부는 해당 revision의 실제 전달 결과를 별도로 따른다. 실제 유료 공급자 호출이나 운영 배포 완료를 뜻하지 않는다.
