# 요청별 현재 판정 서명 확인

새 스택의 캠페인 화면에서 **현재 판정 서명 확인**을 누르면 브라우저가 32바이트 난수를 생성한다. Java 21 API는 조직·프로젝트·사용자·캠페인·고정 버전 해시·MinIO 보관 버전·최신 관리자 검토·OPA 판정을 이 난수와 함께 Ed25519로 서명한다. TypeScript 화면은 전달받은 바이트의 해시와 실제 서명, 요청 난수와 선택 범위를 직접 검증한다.

검토와 판정 조회는 기존 캠페인 검토 잠금 안에서 수행한다. 확인은 저장된 캠페인을 읽으며 새 평가, 관리자 승인 또는 서명 이력 행을 생성하지 않는다. 별도 DB 마이그레이션은 없다. 기존 로그인과 조직·프로젝트 경계, WebFlux 요청 한도를 그대로 적용한다.

## 유효 시간과 화면

- 서명 확인의 유효 시간은 최대 30초다. 승인 필요 캠페인의 통과 결과는 관리자 승인 생성 시각부터 1시간이 되는 시점을 넘지 않는다.
- 요청 난수가 다른 서명 응답, 잘못된 공개키·서명·근거 해시·보관 버전, 다른 사용자·조직·프로젝트·캠페인의 응답은 표시하지 않는다.
- 새 조회를 시작하거나 요청이 실패하면 이전 확인 결과를 지운다. 캠페인 선택과 부모 작업 상태가 바뀌면 진행 중 요청을 취소한다.
- 표시 시간에는 브라우저의 경과 시간도 적용한다. 시스템 시계가 뒤로 이동해도 표시를 무기한 연장하지 않는다. 창으로 돌아올 때 만료도 다시 확인한다.

현재 검토는 확인 이후에도 변경될 수 있다. 이 흐름은 **개발용 서명 확인**이며 `currentDeploymentAuthority=false`다. 과거 영구 보관 서명은 `campaign-gate-observation`, 이번 확인은 `campaign-current-gate-check`로 구분한다. 운영 신뢰키 배포·교체·폐기, 배포 대상에 묶은 단회 토큰과 배포 직전 서버 재검증은 별도 미완료 작업이다. 기존 `/gate` 응답의 `signed=false`는 유지한다.

## API

인증된 조회자·편집자·관리자는 `GET /api/campaigns/{campaign}/gate-check/{challenge}`를 사용한다. challenge는 소문자 16진수 64자리다. POST와 임의 쿼리는 허용하지 않는다. 응답은 `Cache-Control: no-store`이며 공개키는 기존 `/api/gate-trust`에서 제공한다. 이 로컬 개발 키 배포는 운영 신뢰키 관리 완료를 의미하지 않는다.

응답은 payload의 Base64·SHA-256·바이트 수, 서명·알고리즘·key ID·개발 신뢰 도메인을 담는다. payload는 현재 판정, 검토 sequence와 정책 결합, 확인/만료 시각, 요청 challenge와 고정 근거를 포함한다. OPA 또는 보관 근거를 검증할 수 없으면 성공 서명을 발행하지 않는다.

## 검증 범위

Java의 시간·입력 경계 테스트, TypeScript의 실제 Ed25519·변조·재사용·조직 경계·정확한 만료·승인 만료 테스트를 제공한다. 로컬 실제 OIDC→Next.js BFF→WebFlux→Java→OPA/MinIO 경로에서 조회자·관리자의 서명을 독립 검증했고 다른 조직과 잘못된 경로/메서드를 거절했다.

`python scripts/stack-current-gate-check-smoke.py`는 먼저 완료된 참조 정답 캠페인 검사 결과를 찾아 기존 캠페인만 읽는다. 자체 Keycloak/애플리케이션 세션을 종료하며 새 모델 호출이나 평가를 생성하지 않는다. GitHub 소스 통합과 게시 이미지 실행 검증에서도 이 명령을 실행한다. 특정 커밋의 CI 완료 여부는 해당 실행 결과로 별도 확인한다.

브라우저 검사에는 실제 서명 검증, 다른 요청으로 재사용한 응답의 거절, 요청 실패 시 이전 표시 제거와 표시 만료가 포함된다. 로컬 검증은 운영 서버 배포나 배포 권한의 최종 검증을 뜻하지 않는다.
