# 기록된 합성 출력의 문자열 규칙 평가

현재 상태는 소스 구현과 합성 후보 실제 API·브라우저 수용 완료다. 현재 복구 4320 서비스에 적용하지 않았다. [계약 설계](stack-recorded-text-rules-design.md)의 첫 범위만 구현하며 4310의 도구 이벤트·JSON Schema·관리자 정책·범용 connector 전체 이전은 미완료다.

`recorded-text-rules-v1` 에이전트와 데이터셋을 각각 명시 등록하고 기존 캠페인에서 선택해 실행한다. 준비는 로컬 초안만 만들며 기존 작성 중인 사례·에이전트·승인 입력을 변경하지 않는다. 등록이 평가·검토·서명을 자동 실행하지 않는다. 조회자는 준비·등록·실행할 수 없다. 기존 RLS·CSRF·역할·200개 불변 버전 한도와 같은 좌표·같은 내용 재확인/다른 내용409를 유지한다. 범위·역할 변경 시 초안을 제거하고 늦은 응답을 거부한다. 실패 시 초안을 보존한다.

입력·기록 출력은 각각 UTF-8 512바이트, 최대2사례·사례당4규칙이다. 규칙 값은64바이트이며 필수 사례와 필수 규칙을 요구한다. 개별 정규화 사례2048바이트, 정의4096바이트, 전체 작업4096바이트를 확인한다. `contains`와 `not_contains`만 허용하며 대소문자 구분·원래 Unicode 부분 문자열로 비교한다. 정규식·코드·외부 URL·모델·도구 호출은 없다. 빈 출력은 기록된 빈 문자열로 평가하고 누락과 구분한다. 필수 규칙 실패는block, 실행 오류·기한 초과는inconclusive다. reason에 원문을 복제하지 않는다.

기존 DB의 `quality` 평가 분류와 `synthetic` provider를 사용하지만 새 불변 계약을 명시한다. 고정·참조 계약이나 과거 버전 내용을 재해석하지 않는다. 새 DB 시나리오·마이그레이션·인증·정책 설정 변경은 없다. 새 `recordedCase`는 저장된 부모·버전 해시·전체 사례·규칙 ID/필수 여부/순서/개수와 결합하며 기존 `qualityCase`와 섞을 수 없다. Python 결과를 받기 전에 Java에서도 선언된 문자열 규칙과 결과의 정확한 일치를 확인한다.

전용 NATS subject `stack.recorded-text-evaluations`와 소비자를 추가했다. 기존 고정·참조 소비자와 경쟁하지 않는다. 새 `recorded_*` 모듈·실행 프로필과 lifespan 합성으로 연결해 기존 고정·참조 소스 지문을 유지한다. 작업자는 기존 인증된 완료 API만 호출하며 로컬 문자열 평가에1초 제한을 적용한다. 기존120초 완료 기한·취소·중복 완료 동작을 유지한다. 새 진입점은 기존 두 소비자와 새 소비자 준비 상태를 모두 확인한다. 이 런타임 변경도 합성 후보 전용이며 현재 복구 서비스에 적용하지 않았다.

카탈로그·전체 정의·캠페인 검증·기존 사례별 근거 조회에 새 계약을 연결했다. 선택 사례 근거는 실제 기록 출력과 규칙 결과를 정확히 대조해 표시한다. 기록 데이터셋의 새 초안 복사도 계약을 유지한다. 보관·서명 검증은 기존 엄격한 버전 파서를 통해 새 정의를 해시 결합한다. 새 서명 발급 자동화·배포 권한·운영 신뢰 수립을 추가하지 않는다.
