# 원래 스택의 데이터 보존 조회 부하 검사

```powershell
python scripts/stack-readonly-soak.py --minutes 60 --readers 20
```

Next.js BFF·WebFlux·Java·PostgreSQL의 실제 조회 경로를 반복한다. 20개 독립 OIDC 세션을 두 합성 조직에 나누고 `me`, `runs`, `run-history`, `provider-usage`, `campaigns`, `audit`를 60초 간격으로 읽는다. 조직·프로젝트·역할과 응답의 범위/기록 수/예약 합계를 확인한다. 조직별 매 회 60개 보호 요청으로 기존 240회/분 한도를 바꾸지 않는다. 새로운 평가·모델 추론·검토·버전을 만들지 않는다.

시작과 종료 시 모든 public 업무 테이블의 행 수·SHA-256을 대조하고 자기 세션을 닫는다. 지문 불일치, 요청 실패 또는 세션 정리 실패는 미완료다. 업무 행을 생성하는 검사와 서비스 재시작을 동시에 수행하지 않는다. C드라이브 여유가 22 GiB 미만이면 중단한다. 비밀번호·쿠키·토큰·행 내용은 보고서에 기록하지 않는다.

2026-10-11 10:48–11:48 UTC의 로컬 검사에서 60회·7,200개 요청·실패 0건을 확인했다. 실제 관찰 시간은 3,604.05초이며 15개 테이블의 행 수와 내용 해시가 동일했고 자기 세션을 모두 종료했다. 여섯 경로의 최대 p95는 394.263ms, 최대 단일 관측은 1,001.074ms였다. 검사 중 일부 개발용 Docker 빌드도 수행했다.

이는 노트북의 두 합성 조직에서 분당 한 차례 수행한 조회 부하 관측값이다. 지속적인 최대 처리량, 고객 SLA, 실제 모델 처리 성능, 운영 HA 또는 운영 배포 준비를 증명하지 않는다. 검증 범위는 위 여섯 경로이며 이후 추가한 캠페인 이력은 별도의 API·브라우저 검사로 확인한다. 비공개 `.local/stack-readonly-soak-*/summary.json`에 각 경로의 표본 수·p50·p95·최댓값과 보존 근거를 남긴다.
