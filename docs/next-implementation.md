# 다음 구현 작업

확정된 우선순위(2026-10-03): 사용자는 기업 개발팀의 평가 실행과 릴리스 승인 흐름을 선택했다. 첫 구현은 이 흐름을 기준으로 진행한다.

## 첫 구현 단위

합성 데이터셋을 등록하고 모의 에이전트 버전을 평가해 사례별 근거와 게이트 결정을 보여주는 하나의 완결된 흐름을 만든다. 먼저 로컬에서 동작을 확인하고 인증·조직 격리 완료 전 외부 공개를 금지한다.

제안 구조: `apps/web`, `apps/api`, `apps/worker`, `packages/contracts`, `packages/evaluator`, `infra`, `tests`. 워크스페이스와 패키지 선택은 구현 시 지원 버전을 확인해 확정한다.

1. 저장소 개발 규칙·런타임·포맷·CI 기본값과 환경변수 예제를 작성한다. 비밀은 커밋하지 않는다.
2. 버전·사례·실행·규칙 결과·게이트의 계약과 상태 전이를 정의한다.
3. 결정적 evaluator와 mock adapter를 구현한다. 첫 규칙은 필수/금지 문구, JSON 스키마, 도구 허용 정책이다.
4. 고정된 합성 사례로 통과, 업무 회귀, 금지 도구 호출, 실행 오류를 구현한다.
5. 실행 생성/조회와 결과 화면을 연결한다. 원문 출력은 텍스트로 렌더링한다.
6. 다음 단계에서 DB 지속성, 큐 워커, 인증·조직 경계, 감사 이벤트를 연결한다.

## 완료를 판정할 사례

- 동일 버전과 결정적 모의 입력은 동일한 규칙 판정을 반환한다.
- 필수 규칙 실패는 block, 어댑터 오류·필수 증거 누락은 inconclusive다.
- 실행 생성 이후 정책 또는 데이터 변경이 실행 스냅샷을 바꾸지 않는다.
- 입력 출력에 포함된 스크립트가 화면에서 실행되지 않는다.
- 취소·시간 초과·중복 전달은 최종 결과의 중복 확정과 중복 계량을 만들지 않는다(큐 도입 단계).
- 다른 조직의 ID로 실행과 증거에 접근할 수 없다(인증 도입 단계).

## 사용자와 확정할 결정

첫 구매자/주요 시나리오, 기존 에이전트 연결 방법(HTTPS API/SDK/로컬 실행), 민감 데이터 허용 범위, SaaS 또는 고객 환경 설치 요구. 답변 전에는 모의 어댑터와 합성 데이터 기반 평가 코어를 기본 구현 경로로 삼는다.


## 첫 구현 완료 기록 — 2026-10-03

1~5번 작업을 완료했다. Node ESM 기반의 로컬 서버와 UI, 입력 계약, 모의 평가 코어, 불변 스냅샷, 멱등 실행 생성, 결과 JSON 내보내기를 구현했다. 개발·계약 세부 사항은 development.md를 따른다.

다음 단계는 6번: PostgreSQL 지속 저장과 마이그레이션, 인증/조직 권한, 작업 큐와 독립 워커, 감사 이벤트. 취소·시간 초과·중복 전달·조직 간 접근 거절 검증은 이 단계의 완료 조건이다. 현재 구현은 상용화 준비 완료 상태가 아니다.

## 두 번째 구현 완료 기록 — 2026-10-04

6번 작업을 완료했다: PostgreSQL 마이그레이션과 지속 저장, 로컬 키/세션 인증, 조직 RLS와 역할, 독립 워커와 영속 큐, lease 복구와 시도 fencing, 취소·시간·사례 예산, 감사·모의 사용량. Docker의 API/DB/워커를 정지·재시작한 뒤 결과와 사용량 보존을 검증했다.

다음 작업은 제한된 외부 HTTPS 어댑터의 SSRF/egress 통제, 버전 비교와 CI 게이트 연동이다. 그 전에 접근 키의 운영용 관리·OIDC 요구를 결정하고 TLS/비밀 관리·백업 복원 설계를 보완한다. 외부 대상 주소·모델 제공자·배포 지역은 아직 결정하지 않았다. 로컬 v0.2를 상용화 준비 완료로 해석하지 않는다.

## 세 번째 구현 완료 기록 — 2026-10-04

조직별 운영자 allowlist와 endpointHash로 고정한 HTTPS 어댑터, 공인 IPv4 DNS 검증/주소 고정/TLS/응답·시간 제한을 구현했다. 기본 worker는 Docker internal 네트워크로 인터넷 경로가 없으며 외부 연결은 명시적 Compose opt-in을 요구한다. 동일 데이터셋·정책의 버전 결과 비교 API/UI, 기대 버전·유효 시간·증거 전체 범위·해시를 확인하는 조회자 키 기반 CI CLI/API를 구현했다. 사용법과 운영 제약은 release-integration.md에 기록했다.

다음 구현 단위는 운영용 프로젝트 범위 서비스 자격증명과 만료/철회, CI 승인 감사·아티팩트, 백업/복원 검증이다. 외부 대상과 OIDC 제공자, 배포 지역은 미정이다. 실제 외부 호출과 원격 CI 배포를 완료했다고 해석하지 않는다.

## 네 번째 구현 기록 — 2026-10-04 자율 개발

프로젝트 범위 CI 전용 키(만료·철회·발급자 상태 확인), 단일 게이트 경로 권한, append-only 릴리스 검증 기록과 JSON 아티팩트, 관리자 키 관리/프로젝트 검증 기록 UI를 구현했다. DB 스냅샷 기반 dump와 별도 DB 복원 roundtrip의 데이터 지문·RLS·연결 차단을 검증했다. 사용법은 ci-operations.md와 backup-recovery.md를 따른다.

다음 우선순위: 승인 검증 요청의 중복 처리·호출/저장량 통제, 키·승인 이력의 프로젝트 선택/페이지 조회, 백업 암호화와 복원 권한 검증 확대, 신뢰 가능한 승인 아티팩트의 서명 설계. OIDC/원격 runner는 제공자와 배포 대상이 정해지기 전 연결하지 않는다.

## 다섯 번째 구현 기록 — 자율 개발

승인 검증의 호출 주체·프로젝트별 중복 방지, 병렬 전달의 단일 기록/감사, 과거 승인 재사용 시 상태·유효 시간 재검증, 조직별 호출·저장량 상한을 구현했다. 세션의 프로젝트 선택과 CI 키의 프로젝트 고정, 늦게 도착한 응답의 화면 덮어쓰기 방지를 추가했다.

다음 단위는 백업 암호화·복원 보안 속성 검사와 DB 인증 함수의 최소 권한화다. 이어서 프로젝트와 에이전트/정책 버전 관리 UI, 승인 아티팩트 서명과 운영 준비 점검을 진행한다. 실제 OIDC/외부 API/배포는 여전히 비활성 상태다.

## v0.6 완료

CI 조회 함수의 전용 NOLOGIN 읽기 역할 적용, AES-256-GCM 로컬 백업, 복원 전 인증 검증, 복원 시 함수 소유자 유지와 보안 카탈로그 지문 비교를 완료했다. 전체 43개 테스트와 실제 암호화 roundtrip이 통과했다. 다음 우선순위는 프로젝트 생성 및 에이전트·정책 버전 등록 화면, 릴리스 근거 서명과 검증 절차다.

## v0.7 완료

관리자 프로젝트 생성과 조직별 최대 100개 제한, 동시 요청 중복 처리 및 감사, 모의 에이전트·정책 버전 등록 UI를 완료했다. 새 프로젝트를 만들고 세 가지 버전을 등록한 뒤 실제 Docker 워커 평가 PASS까지 화면에서 확인했다. 전체 45개 테스트가 통과했다. 다음 우선순위는 승인 근거 서명·검증 및 운영 준비 점검이다.

## v0.8 완료

개발용 Ed25519 키 생성·보존, API 전용 secret 연결, 불변 릴리스 기록의 서명, 공개키 기반 온라인/오프라인 검증을 구현했다. 과거 unsigned 기록은 보존하며 서명 검증은 과거 증거 확인에 한정한다. 47개 테스트와 실제 Docker 서명 영수증의 오프라인 검증을 통과했다. 다음 작업은 프로젝트 조회 경험·대량 기록 조회·운영 상태 진단 및 평가 실패 분석 흐름이다.

## v0.9 완료

프로젝트 범위 CI 키 조회, 키·검증 이력 cursor pagination과 더 보기 UI, CI 키의 분당 발급/총 이력 제한을 추가했다. 49개 테스트와 마이크로초 정밀도 paging 회귀 검증이 통과했다. CI 환경의 signing key 경로 생성도 플랫폼 절대 경로를 사용하도록 보완했다. 다음은 운영 상태와 실패 진단 흐름이다.

## v0.10 완료

워커가 DB 시간으로 2초마다 heartbeat를 기록하고 관리자 운영 화면에서 최근 15초 신호·프로젝트 대기/실행/기한 초과·lease 만료·24시간 완료/오류 수를 확인한다. 미래 또는 오래된 신호는 정상으로 표시하지 않는다. heartbeat는 테넌트 내용 없는 전역 인프라 신호이며 실행 집계는 조직/프로젝트로 제한한다. 50개 테스트와 실제 Docker 화면 검증을 통과했다. 다음은 실행 기록 페이지 조회, 실패 분석과 승인 기록 연결, 보안·복원 심화 검토다.

## v0.11 완료

실행 기록의 상태/판정 필터, 프로젝트·필터 고정 cursor, 요약만 읽는 DB 쿼리와 더 보기 UI, 독립 기준 실행 선택을 완료했다. 전체 51개 테스트가 통과했다. 다음은 수동 검토가 필요한 정책의 관리자 승인 흐름과 현재 최종 게이트 확인이다.

## v0.12 완료

선택적 관리자 검토 정책, 자동 평가 통과와 최종 배포 허용 분리, 불변 승인/반려 기록·감사, 증거·검토자 권한·TTL·최신 DB 순서를 확인하는 최종 CI 게이트를 구현했다. 실제 Docker mock 흐름에서 승인 전 차단·승인 후 서명 검증·반려 후 차단을 확인했다. 대기 후 CI 자격증명 만료 재검증과 DB의 수동 정책 불변성도 강화했다. 다음은 실행 완료 권한 분리·복원 카탈로그 검증 심화·대량 백업의 메모리 제한과 운영 준비 검토다.

## v0.13 완료

인증 전 조회를 전용 NOLOGIN 역할의 고정 함수로 이동하고 조직·멤버십·접근 키·세션에 tenant RLS를 적용했다. 로그인 잠금 대기 후 자격증명 재검증과 API의 워커 결과 위조 방지를 DB 트리거로 강제했다. 전체 56개 테스트, 실제 Docker 인증/평가/서명 검증, 변경된 권한의 backup roundtrip을 확인했다. 다음 작업은 복원된 인증 격리 기능 검사 확대와 대량 백업 메모리 제한이다.
