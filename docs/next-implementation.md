# 다음 구현 작업

확정된 우선순위(2026-10-03): 사용자는 기업 개발팀의 평가 실행과 릴리스 승인 흐름을 선택했다. 첫 구현은 이 흐름을 기준으로 진행한다.

## 기존 조직을 선택하는 기본·비교 시연 — v0.141

`demo:portfolio -- --organization-index 1`은 기존 두 번째 조직의 관리자 키·프로젝트를 선택한다. 비교·자료 저장 옵션과 함께 사용할 수 있으며 기본 첫 조직의 동작은 유지한다. 로그인한 조직·프로젝트·역할이 선택한 범위와 다르면 시나리오 조회나 평가 생성 전에 중단하고 자체 로그아웃한다. 선택 인덱스·조직·프로젝트와 세션 범위 확인은 비공개 보고서에 기록하며 접근 키·쿠키는 기록하지 않는다. 잘못된·중복·없는 선택을 요청 전에 거절한다. 현재 고정 완료 기준선과 실제 CI·이미지 검증 범위는 아래 현재 상태와 완료 범위에 기록한다.

## 조직 선택을 유지한 역할·교차 조직 시연 — v0.142

역할 시연도 기존 조직을 선택한다. 선택 조직의 세 역할과 다른 기존 조직 조회자의 네 세션 범위를 확인하며, outsider 조직·프로젝트가 선택 범위와 같으면 거절한다. 불일치 세션은 시나리오 읽기·평가 생성 전에 중단하고 열었던 세션을 종료한다. 기본 선택의 동작과 실제 403/404 경계는 유지한다. 다른 조직의 세션 불일치 세 경우와 선택 인자를 실제 subprocess로 확인한다.

## 선택 조직의 서명·검토 감사 자료 — v0.143

`demo:evidence`는 기존 조직 선택을 자식 비교 시연과 자료 목록 범위, 조회자 세션까지 전달한다. 선택 인자만으로 검토 의견 자료 형식을 켜지 않고 기존 기본 영수증 형식을 유지한다. `--with-report`는 기존처럼 `--with-reviews`를 요구하며 없는 조직과 잘못된 선택은 시연 실행 전에 거절한다. 실제 자식 CLI의 잘못된 로그인 범위를 생성 전 거절하고 세션을 종료하는 경로를 회귀 검사했다. 현재 배포 허용은 과거 자료 검증과 별개이며 HTML 시각 검증 제한은 유지한다.

## 시연 계획 전체의 실행 용량 확인 — v0.144

기본·비교 시연과 역할 시연이 생성할 4·6·1개 실행의 보관 공간과 동시 슬롯을 로그인 범위 확인 후 검사한다. 부족·다른 조직·잘못된 수치는 정책이나 평가 생성 전에 중단하며 자체 세션을 종료한다. 비교 자료의 자식 시연도 같은 검사를 따른다. 연속 평가와 공통 검사 함수를 사용하되 기존 한도·서버 원자성·멱등 순서는 유지한다. 실제 CLI의 부족·가득 찬 슬롯·틀린 범위·잘못된 수치와 정확한 용량 경계, 역할 세션 네 개 정리를 검사했다. CI의 소스와 registry 이미지에서 두 번째 조직의 비교·의견 자료·역할 시연을 추가로 검증한다. 관측은 용량 예약이 아니다.

## 운영 상태 재조회와 용량 표시 경계 — v0.145~v0.146

직접 조회와 감사 연동 조회가 공유하는 순서를 사용해 늦은 응답의 덮어쓰기를 막는다. 조회 중 이전 수치를 정리하고 실패 안내와 재시도를 운영 패널 안에 표시한다. 별도 미리보기에서 서버 연결 실패와 복구를 확인했으며 Docker 관측은 유지했다. 용량 값은 현재 로그인 조직과 일관된 관측 수치일 때만 표시하고 실행 요청의 서버 한도 검사는 유지한다. 로컬·실제 CI·이미지 검증의 완료 범위는 포트폴리오 완료 범위에 따로 기록한다.

## 감사 기록의 조회·실패·재시도 안내 — v0.147

감사 패널 안에 조회 중, 빈 조건, 표시 수와 마지막 페이지를 안내한다. 이전 페이지 실패는 기존 행과 커서를 보존하고 재시도하며, 같은 커서의 중복 클릭은 막는다. 새 조건이나 로그아웃은 이전 응답을 무효화한다. 감사·사용량·운영 상태의 묶음 중 하나가 실패하면 빈 성공으로 표시하지 않는다.

## 조직·프로젝트가 확인된 조회 측정 — v0.148

메타데이터 측정은 역할뿐 아니라 선택한 조직·프로젝트의 로그인 범위를 확인한다. 기존 조직 선택과 올바른 프로젝트 헤더를 지원하며 잘못된 세션에서는 측정 조회 전에 중단하고 자체 로그아웃한다. 범위 정보는 비공개 보고서에 남기고 CI의 소스·이미지 양쪽에서 두 번째 조직의 짧은 동시 조회 측정을 추가한다. 지연 표본은 평가 워커 처리량이나 SLA로 해석하지 않는다.

## 병렬 합성 생성의 조직 선택과 계량 경계 — v0.149

병렬 합성 시연도 기존 조직의 작성자 범위를 생성 전에 확인한다. 선택 프로젝트 헤더와 조직·프로젝트에 한정한 SQL 대조를 사용하고, 중복 생성 수렴·서명·사용량·감사와 실패 정리의 기존 검사를 유지한다. 관리자 조회 권한이나 한도를 늘리지 않는다. CI의 소스·이미지 양쪽에서 두 번째 조직의 짧은 병렬 시연을 추가한다.

## 선택 조직의 시연 준비 점검 — v0.150

`demo:preflight -- --organization-index 1`은 서버·파일 준비 확인에 이어 선택 조직의 관리자 세션 범위와 최근 워커 신호, 비교 시연용 6개 실행의 보관 공간·최소 한 동시 슬롯을 확인한다. 범위가 틀리면 운영 조회 전에 멈추며 성공·실패 모두 자체 로그아웃한다. 실패 안내는 원문 오류나 키·쿠키를 노출하지 않는다. 로그인·로그아웃 외에 업무 데이터를 생성·수정하지 않는다. 인자 없는 점검은 기존 읽기 전용 동작을 유지한다. CI 소스와 registry 양쪽의 선택 조직 시연 앞에 이 점검을 추가했다. 이 기능은 고객 연결이나 기업 인증 제공자 연결을 대신하지 않는다.

## 병렬 시연 전체의 용량 확인 — v0.151

선택 작성자 세션의 범위 확인 후 기존 합성 도구의 DB 계량 연결로 조직 전체 보관량과 활성 실행을 관측한다. 전체 고유 실행 수와 최대 네 개의 병렬 실행 슬롯을 확인하며 부족·관측 오류는 시나리오 조회와 생성 전에 중단한다. 같은 조직의 다른 프로젝트도 조직 한도에 포함하고 다른 조직은 포함하지 않는다. 네 중복 요청은 한 실행으로 계산한다. 원문 DB 오류·응답은 보고서에 복사하지 않으며 실패 경로에서도 자체 로그아웃한다. 관측은 용량 예약이 아니고 서버 한도·멱등 처리·역할 권한은 유지한다.

## 고객 연결의 오프라인 요청·응답 계약 점검 — v0.152

외부 호출 전 요청·응답 JSON을 실제 HTTPS 어댑터와 같은 계약으로 검사한다. 기본 공개 예제는 합성이며 지정 파일은 원문·경로·원문 오류를 출력하지 않는다. 요청 검증은 DNS 조회 전 이루어지고 데이터셋 mock·규칙·정책은 전송하지 않는다. 계약 통과와 실제 연결·릴리스 승인을 구분한다. CI는 소스의 합성 파일과 정확한 registry worker 이미지 내부의 계약 검사를 실행한다. 사용법은 [연결 계약 점검](connector-contract.md)을 따른다.

## 고객 응답 기록의 오프라인 평가 재현 — v0.153

기록의 사례·입력·에이전트 버전을 데이터셋과 결합한 뒤 기존 평가 코어를 적용한다. 누락·잘못된 증거는 모의 값으로 대체하지 않고 불확정으로 평가한다. 다른 사례·입력·버전이나 중복 항목은 평가 전에 거절한다. 출력은 집계와 사례 번호만 포함하며 기록 출처·원격 코드 동일성·현재 릴리스 승인을 증명하지 않는다. CI는 소스 예제와 worker 이미지 내부의 재현 코드를 각각 확인한다. [연결 계약 점검](connector-contract.md)의 기록 재현 절차를 따른다.

## 이전 자율 개발 창에서 완료한 포트폴리오 검증 — v0.113 역사 기록

1. 세 서버 버전의 여덟 순차 구간에서 중복 없는 2,160개 실행·기대 판정·사용량·종료 감사·자체 세션 정리를 확인했다. 미완료 실행이나 이전 작업 창은 합산하지 않았다.
2. 최신 검증 이미지의 기존 설치 실행과 별도 암호화 백업의 격리 복원을 확인했다. LogiTrack과 기존 키·백업·19개 마이그레이션을 보존했다.
3. 실제 화면에서 정상 통과와 비교 통과·관리자 반려의 최종 차단을 확인하고 촬영 버전을 기록했다. API 파일·오프라인 CLI 검증과 브라우저 버튼 활성화를 구분했다.
4. 고정 CI의 333개 테스트·네 작업·실제 전달 묶음과 관측 환경을 문서에 연결했다. 기본 시연·비교 옵션·역할 시연을 자동화했다. 다음 제품 단계의 고객 사례·성공 기준·인증 운영·staging 요구는 아직 미정이다.

## 최초 구현 계획 (완료 이력)

합성 데이터셋을 등록하고 모의 에이전트 버전을 평가해 사례별 근거와 게이트 결정을 보여주는 하나의 완결된 흐름을 만든다. 먼저 로컬에서 동작을 확인하고 인증·조직 격리 완료 전 외부 공개를 금지한다.

제안 구조: `apps/web`, `apps/api`, `apps/worker`, `packages/contracts`, `packages/evaluator`, `infra`, `tests`. 워크스페이스와 패키지 선택은 구현 시 지원 버전을 확인해 확정한다.

1. 저장소 개발 규칙·런타임·포맷·CI 기본값과 환경변수 예제를 작성한다. 비밀은 커밋하지 않는다.
2. 버전·사례·실행·규칙 결과·게이트의 계약과 상태 전이를 정의한다.
3. 결정적 evaluator와 mock adapter를 구현한다. 첫 규칙은 필수/금지 문구, JSON 스키마, 도구 허용 정책이다.
4. 고정된 합성 사례로 통과, 업무 회귀, 금지 도구 호출, 실행 오류를 구현한다.
5. 실행 생성/조회와 결과 화면을 연결한다. 원문 출력은 텍스트로 렌더링한다.
6. 다음 단계에서 DB 지속성, 큐 워커, 인증·조직 경계, 감사 이벤트를 연결한다.

## 완료를 판정할 사례

- 동일 버전과 결정적 모의 입력은 동일한 규칙 판정을 반환한다.
- 필수 규칙 실패는 block, 어댑터 오류·필수 증거 누락은 inconclusive다.
- 실행 생성 이후 정책 또는 데이터 변경이 실행 스냅샷을 바꾸지 않는다.
- 입력 출력에 포함된 스크립트가 화면에서 실행되지 않는다.
- 취소·시간 초과·중복 전달은 최종 결과의 중복 확정과 중복 계량을 만들지 않는다(큐 도입 단계).
- 다른 조직의 ID로 실행과 증거에 접근할 수 없다(인증 도입 단계).

## 사용자와 확정할 결정

첫 구매자/주요 시나리오, 기존 에이전트 연결 방법(HTTPS API/SDK/로컬 실행), 민감 데이터 허용 범위, SaaS 또는 고객 환경 설치 요구. 답변 전에는 모의 어댑터와 합성 데이터 기반 평가 코어를 기본 구현 경로로 삼는다.

최종 게이트에서 비교의 evaluationPassed와 전체 배포 허용을 구분한다. 관리자 검토 정책은 비교 통과와 승인 대기를 동시에 표시할 수 있다. 비교 가능 근거가 부족하면 미완료로 표시하며, 변경·회귀 규칙 수와 최대 10개 회귀 세부를 텍스트로 보여준다. 전체 근거는 원본 검증 기록 JSON에 유지한다. 서버 판단이나 승인 권한은 변경하지 않는다.

## v0.52 — 회귀 사례 근거로 이동

최종 비교의 회귀 규칙에서 후보의 정확한 사례로 이동한다. 부분 문자열 검색 대신 사례 ID를 정확히 선택하고 기존 검색·필터를 해제한다. 선택 해제 또는 검색·필터 변경으로 전체 탐색에 복귀한다. 요약·판정·원본 JSON은 전체 실행 기준을 유지한다. 이전 링크는 기준·검토·실행·워크스페이스 변경 뒤 사용할 수 없다.

## v0.53 — CI 입력 선검증

릴리스 CLI는 후보·세 버전 UUID와 선택적 기준/프로젝트 UUID, 검증 키 형식, 비어 있지 않은 접근 키, 유효 시간 범위를 네트워크 요청 전에 확인한다. 후보 자신은 기준으로 지정할 수 없다. 잘못된 설정은 고정 오류와 종료 코드 2로 종료하며 인증 요청이나 서버 기록을 만들지 않는다. UUID 존재·프로젝트 접근 권한·근거·서명은 기존 서버 및 영수증 검증이 확인한다.

## v0.54 — CI 응답 의미 검증

CLI는 해시가 일치하더라도 판정과 배포 허용의 모순, 잘못된 사유 목록, 통과 응답의 차단 사유를 거절한다. 기준 요청은 비교의 후보·기준 ID와 결합하고, 전체 통과는 비교 가능 근거와 비교 평가 통과를 요구한다. 관리자 정책의 evaluationPassed와 별도 승인을 구분한다. 이 검사는 서버 근거·권한 검사나 신뢰 공개키 서명 검증을 대체하지 않는다.

## v0.55 — CI 검증 기록 파일 저장

`AGENTTRUST_RECEIPT_OUTPUT_FILE`을 지정하면 검증된 응답의 원본 artifact·artifactHash·선택적 signature를 JSON 파일에 저장한다. 통과·차단을 모두 저장하며 기존 파일은 덮어쓰지 않는다. 부모 디렉터리는 미리 준비하고 파이프라인 실행별 고유 경로를 사용한다. 저장 실패는 종료 코드 2로 처리하여 성공으로 진행하지 않는다. 파일 저장 자체는 서명 검증·현재 배포 권한 확인을 대체하지 않는다. 신뢰 공개키 검증에는 기존 `AGENTTRUST_RECEIPT_PUBLIC_KEY_FILE`을 함께 지정한다.

## v0.57 — CI 응답 읽기 제한

릴리스 CLI는 응답 스트림을 최대 8 MiB까지 읽고 UTF-8 및 JSON을 검사한다. 크기 초과 시 스트림 읽기를 취소하며, 잘못된 응답은 검증·파일 저장으로 진행하지 않고 종료 코드 2를 반환한다. 분할된 다중 바이트 UTF-8을 지원한다. 기존 요청 타임아웃·루프백 URL·리디렉션 거절을 유지한다.

`AGENTTRUST_PROJECT_ID`를 지정하면 CLI는 반환된 artifact.projectId가 같은 UUID인지 추가 확인한다. 다른 프로젝트 또는 프로젝트 필드가 없는 응답은 해시가 일치해도 거절한다. 지정하지 않은 기존 프로젝트 키 경로는 서버의 고정 범위를 사용한다. 이 검사는 서버 권한·조직 검사 및 신뢰 공개키 검증을 대체하지 않는다.

## v0.60 — CI UUID 정규화

유효한 후보·기준·프로젝트·세 버전 UUID는 요청 전에 소문자로 정규화한다. 대문자 UUID가 PostgreSQL의 소문자 응답과 달라 성공한 게이트를 오류로 판단하는 일을 방지한다. 검증 키와 접근 키는 변환하지 않으며 공백·잘못된 UUID·후보와 같은 기준은 계속 거절한다. 호출자가 전달한 객체는 변경하지 않는다.

## 브라우저 응답 읽기의 크기·문자열·오류 경계 — v0.95

실제 UI 핸들러를 네이티브 Response/ReadableStream 모의 응답으로 실행해 잘못된 UTF-8이 대체 문자로 읽혀 최종 통과를 표시하고 손상 JSON 파서 오류가 합성 원문 canary를 표시하는 변경 전 실패를 재현했다. 8 MiB 스트림 한도와 엄격한 UTF-8/JSON 읽기를 적용한다. 초과 시 읽기를 취소하고 reader lock을 정리한다. 전송·파서 원문 오류 대신 고정된 재조회 안내를 사용하고 기존 15초 deadline와 이전 scope 결과 거절은 유지한다. 서버 HTTP 오류의 문자열 메시지만 제한된 길이로 표시한다.

손상 JSON·UTF-8·한도 초과는 실패로 표시하고 현재 기록 저장을 활성화하지 않는다. 버튼 잠금 정리와 정상 재확인·서명 기록 저장도 검증했다. 기존 초기 hydration/로그인 실패 테스트는 원문 오류 노출 대신 고정 안내와 화면 복구를 확인한다. 위협 모델에서 현재 구현과 OIDC·비밀 저장소·서명된 이미지 출처 인증 등 미구현 운영 목표를 구분하고, 최대 100개 사례·2,000개 규칙의 실제 합성 API/브라우저 점검을 기록한다.

## 초기화 대상의 로컬 설정 검증 — v0.98

서명 검증은 PUBLIC KEY 시작만 확인하던 입력을 단일 공개 SPKI PEM 전체로 제한한다. 공개키 뒤의 두 번째 키·private key·원문과 1 KiB 초과 파일을 거절하고 Ed25519 타입 검사를 유지한다. CI 릴리스 CLI는 신뢰키 파일을 제한된 버퍼와 엄격한 UTF-8로 읽고 인증 요청 전에 검증한다. 오프라인 CLI도 같은 reader를 사용해 키를 먼저 검증한다.

변경 전 단일 키 뒤에 다른 PEM이 붙어 있어도 통과한 두 실패를 실제 자식 CLI와 공유 검증에서 재현했다. 수정 후 원문·비밀 노출 없이 거절하고 네트워크 요청이 없음을 확인한다. 정확한 바이트 한도, 손상 UTF-8, 빈/없는 파일·디렉터리, CRLF와 정상 서명·대형 기록 검증을 유지한다. 키를 자동 선택하거나 private key에서 신뢰 공개키를 추출하지 않는다.

주기 조회·중복 클릭, 성공/오류/시간 초과가 먼저 완료되는 세 경합, 요청 실패 후 명시적 재시도와 이전 취소가 새 선택의 취소 잠금을 해제하지 않는지 확인한다. 서버의 최종 확정 fencing과 정확히 한 번 사용량·감사는 변경하지 않는다. 네트워크 실패는 서버에서 처리됐을 수 있다는 기존 재조회 안내를 유지하며 자동 재전송하지 않는다.

## 제한된 동시 메타데이터 조회 측정 — v0.104

## 버전 목록 갱신 완료의 원래 프로젝트 범위 유지 — v0.111

프로젝트 전환으로 비운 버전 선택과 실행 버튼 잠금을 유지하며 새 범위의 정상 초기화는 계속 진행한다. 버전 내용·불변성·등록 API·기존 데이터를 변경하지 않고 요청을 재전송하지 않는다.


## 최종 통과 응답과 평가·비교·승인 의미의 일치 — v0.112

응답의 전체 판정과 저장된 artifact가 일치하더라도, 비교가 미완료이거나 관리자 승인이 없거나 조회한 평가가 통과하지 않은 상황에서 화면이 최종 통과를 표시할 수 있었다. 실제 UI 핸들러에 자체 서명된 합성 응답을 주어 변경 전 세 실패를 재현했다. 최종 허용은 조회한 완료 평가의 pass와 정책별 허용/평가 통과 상태, 선택한 기준·후보 ID와 완전하고 회귀 없는 비교, 관리자 정책의 명시적 승인 상태를 함께 요구한다. 모순은 확인 실패·명시적 재시도 안내로 처리하고 기록 저장을 활성화하지 않는다.

관리자 정책의 comparison.evaluationPassed와 comparison.deploymentAllowed를 구분한다. 비교 자체가 통과하고 후보의 현재 승인이 유효하면 전체 허용이 가능하며, 비교 통과만으로 승인 대기·반려·만료를 우회하지 못한다. 정상 비교와 관리자 승인 응답의 원본 artifact·해시·서명 저장 및 독립 서명 검증을 유지한다. 화면의 의미 검사는 서버 평가 재실행이나 독립 키의 암호학적 서명 검증을 대신하지 않는다.


## 기준 실행을 포함하는 자동 포트폴리오 시연 — v0.113

`npm run demo:portfolio -- --compare`는 기존 기본 시연을 유지하며 정책별 합성 기준 2개를 추가한다. 6개 평가·6개 게이트의 12단계에서 기준 근거 결합·비교 의미·독립 서명을 확인하고 승인 대기·승인·반려의 최종 허용을 구분한다. 잘못된 기준·모순인 비교·서명 또는 정리 실패는 성공으로 처리하지 않는다. 미완료 기준도 취소하며 승인 후 실패한 후보는 반려로 정리한다. 자체 세션은 종료하고 기존 데이터·키는 보존한다.

실제 로컬 API에서 비교 옵션의 12단계와 서명·정리를 확인했다. 기본 흐름 유지, 두 정책 기준 결합, 서명 검사 성공에도 잘못된 비교 거절, 승인 후 정리와 미완료 기준 취소, 잘못된 CLI 인자의 인증 전 거절, 비교 모드 로그인 응답 크기·UTF-8 경계를 테스트한다. CI 합성 시연 단계에도 비교 옵션을 포함한다. 기존 서버에서 실행한 도구 검증과 새 이미지 실행 검증은 별도로 기록한다.

## 과거 검증 기록 상세와 본문 해시 확인 — v0.119

## 검증 기록 조건 조회 — v0.120

‘검증 기록 판정’과 ‘검증 기록 후보 실행 UUID’를 입력하고 ‘기록 조건 적용’을 누르면 서버가 같은 조직/프로젝트의 기록만 좁혀 조회한다. 조건 입력 중에는 기존 적용 조건을 유지하며 이전 페이지도 적용 조건으로 조회한다. ‘조건 초기화’는 전체 기록으로 돌아간다. 일치하지 않는 후보는 빈 목록으로 표시하고 다른 조직의 존재 여부를 공개하지 않는다.

새 조건을 적용하면 이전 목록·페이지 커서·과거 상세를 지운다. 지연된 이전 조건 응답과 로그아웃 후 응답은 결과를 복원하지 않는다. 서버의 페이지 커서는 판정·정규화한 후보 UUID·기록 리소스에 묶여 다른 조건이나 CI 키 목록에서 재사용할 수 없다. 이전 버전의 검증 기록 커서를 이어 쓰려면 새로고침해야 한다.

`demo:evidence`는 오프라인 검증 뒤 자체 viewer 세션으로 원래 네 후보·통과/차단 조건의 페이지를 조회한다. 여섯 서명 artifact에서 확인한 ID·본문 해시·판정·후보/기준·확인 시각·서명 키와 목록 메타데이터를 대조하고 중복·누락·과대 커서를 거절한다. 목록에 전체 근거가 섞이지 않는지 확인하고 자체 세션을 종료한다. 이 단계는 과거 기록의 조회 정합성이며 현재 배포 권한 확인이 아니다.


## 연결된 과거 관리자 검토 근거 — v0.121

검증 기록 상세는 기록에 포함된 검토 ID·해시에 해당하는 원래 관리자 의견을 조회한다. 조직/프로젝트·후보 실행·스냅샷/결과 해시·검토 판정·시각과 실제 본문 해시를 결합한 뒤 텍스트로 표시한다. 나중에 반려가 추가되거나 검토자의 권한이 바뀌어도 과거 의견 조회는 현재 승인을 복원하지 않는다. 연결된 검토가 없거나 모순이면 확인된 검증 기록은 유지하며 별도 실패 안내를 표시한다. 서명 검증은 독립 공개키 CLI의 책임으로 유지한다.

서버는 검토 해시와 함께 저장 행의 ID·조직·프로젝트·실행·검토자·판정·시각을 대조한다. 올바른 해시를 가진 모순된 본문도 목록·상세·최종 게이트에서 503으로 차단하고 의견 원문을 오류에 포함하지 않는다. 이를 변경 전 실패로 재현했다. `demo:evidence`의 viewer 단계도 원래 승인·반려 의견 두 개를 조회해 서명 artifact에 포함된 ID·해시와 대조한다.

상세 닫기는 원래 버튼 또는 기록 패널로 키보드 포커스를 돌려준다. 검색 결과가 없는 경우는 전체 기록이 없는 경우와 안내를 구분한다. 로그아웃·닫기·조회 조건 초기화 뒤의 늦은 의견 응답이나 해시 계산이 이전 상세를 복원하지 않는다.


## 원래 검토 의견을 포함한 오프라인 감사 자료 — v0.122

`npm.cmd run demo:evidence -- --with-reviews`는 기존 여섯 서명 기록과 연결된 승인·반려 의견 두 개를 새 schemaVersion 2 묶음으로 저장한다. 기본 명령과 기존 schemaVersion 1 묶음 검증은 유지한다. 새 묶음은 manifest.json, receipt-1.json~receipt-6.json, review-1.json~review-2.json의 정확한 아홉 일반 파일만 허용한다. 의견 본문과 목록은 각각 64 KiB, 영수증은 기존 제한을 적용하고 심볼릭 링크·추가/누락 파일·잘못된 UTF-8을 거절한다.

기존 데모의 정리와 로그아웃, 자체 viewer 세션의 원래 검토 조회와 로그아웃까지 성공한 뒤에만 의견을 포함한 묶음을 쓴다. 별도 오프라인 CLI는 독립 신뢰 공개키로 여섯 Ed25519 서명을 먼저 확인하고, 서명 artifact가 지정한 원래 검토 ID·해시·조직/프로젝트·후보 실행·평가 해시·판정·시각을 의견 본문과 결합한다. 파일/목록 체크섬을 다시 계산해도 서명된 참조와 다른 의견은 거절한다. 의견 파일의 해시 자체를 별도 서명으로 표현하지 않는다.

같은 `demo:evidence:verify` 명령으로 검증하며 새 형식은 `reviewBodiesVerifiedOffline: true`, `linkedReviewsVerified: 2`를 반환한다. 목록 SHA-256 일치는 전달된 값과의 일치이며 별도 목록 서명이나 신뢰 경로의 증명이 아니다. 과거 의견과 영수증은 현재 승인·현재 관리자 권한·현재 배포 허용을 보장하지 않는다. 접근 키, 서명 비밀키, 평가 원문 입출력은 포함하지 않는다. 실제 의견은 기밀일 수 있으므로 내보낸 자료의 전달 대상은 운영자가 정한다.


## 조회 범위가 바뀐 과거 기록 다운로드 — v0.123

기록 JSON 저장은 버튼을 만든 로그인 범위와 원래 목록에 묶인다. 조건 적용·초기화·전체 새로고침이 시작되면 이전 목록의 진행 중 다운로드와 오류 안내를 무효화한다. 응답을 기다리는 동안뿐 아니라 본문 해시 확인 중에도 변경 여부를 확인한다. 이전 로그인/목록의 분리된 버튼은 요청을 보내지 않는다. 다음 페이지를 추가하는 동작은 기존 목록을 유지하므로 이미 요청한 다운로드도 유지한다. 조회 조건 초기화, 목록 교체 후 늦은 오류, 재로그인 후 이전 버튼 동작을 수정 전 실패로 재현했고 현재 다운로드와 페이지 추가 호환성도 검증했다.


## 읽기용 오프라인 감사 보고서 — v0.124

`npm.cmd run demo:evidence -- --with-reviews --with-report`는 여섯 서명 기록과 원래 검토 의견 두 개를 검증한 뒤 원본 묶음 밖의 새 `.local/portfolio-audit-<UUID>.html`을 생성한다. 기존 자료에서 보고서를 만들려면 [감사 보고서 안내](portfolio-audit.md)를 따른다. 보고서는 과거 판단·고정 버전·후보/기준·해시·원래 검토 의견을 표시하며 현재 배포 허용을 확인했다고 주장하지 않는다. HTML 자체는 별도 서명되지 않은 사본이므로 원본 묶음과 신뢰 공개키의 재검증이 필요하다.

의견·이유·ID는 HTML 텍스트로 이스케이프하고 스크립트·외부 자원 없는 문서로 만든다. 출처 서명/파일 검증이 실패하면 보고서를 만들지 않고 오류 입력을 출력하지 않는다. 기존 파일은 덮어쓰지 않으며 원본 폴더 또는 디렉터리 별칭을 통한 그 하위 경로도 출력 대상으로 거절한다. 기존/새 자료 형식·실제 서명 의견의 마크업·별도 CLI·기존 파일/원본 목록 보존·별칭 경계를 테스트하고 실제 로컬 API의 자료로 생성했다. 로컬 HTML URL의 브라우저 열기는 보안 정책이 차단했으므로 이 기록은 화면의 시각 검증을 완료했다고 주장하지 않는다.


## 기록 새로고침의 이전 목록 정리 — v0.125

## 일반 HTML 파일로 제한한 감사 보고서 출력 — v0.129

## 범위를 명시한 장시간 합성 검증 — v0.137

기존 로컬 자격증명 파일의 조직 인덱스를 선택하고 고정된 조직·프로젝트·관리자 세션을 평가 전 확인한다. 요청 헤더와 최종 결과, 한 번 사용량·종료 감사 검사도 같은 범위에 묶는다. 기본 첫 조직은 유지하며 두 번째 조직의 반복 검증도 기존 키와 한도 안에서 수행한다. 잘못된 조직·프로젝트·역할 세션에서는 목록 조회·평가 생성 전에 중단하고 자체 로그아웃한다. 선택 동작을 수정 전 실패로 재현했고 실제 CLI의 세 범위 불일치·잘못된 인자·기존 로그인 실패 정리를 포함한 관련 7개 검사와 전체 444개 테스트·구문 검사가 통과했다. [실행 방법](operations.md#반복-평가-검증-v041)을 따른다.

## 실행 기록의 조회 상태 안내 — v0.138

실행 기록 목록 안에서 조회 중, 조건에 맞는 빈 결과, 현재 표시 수와 추가 페이지 유무를 안내한다. 전체 재조회 실패는 빈 목록과 재시도 안내를 함께 표시하고, 이전 페이지 추가 조회 실패는 이미 표시된 기록을 유지하면서 재시도를 안내한다. 조직·프로젝트 전환과 로그아웃은 안내도 초기화하며 늦은 과거 실패가 최신 상태를 바꾸지 않는다. 필터·조회 권한·기준 실행 선택·게이트 판정은 기존 동작을 따른다.

## 조직 실행 용량 관측과 두 조직 CI 검증 — v0.139

관리자용 운영 API/화면에서 조직 전체 보관·동시 실행의 사용 수, 기존 한도와 남은 수를 표시한다. 프로젝트 대기열과 조직 한도를 구분하며 조회 시각과 요청 시 재검사를 안내한다. 한도 자체와 조직/역할 권한은 유지한다. CI의 소스 및 registry 이미지 검증에서 두 기존 시연 조직의 범위별 연속 평가·정확히 한 번의 사용량/감사·자체 로그아웃을 순차 수행한다.

## 연속 평가의 실행 전 용량 확인 — v0.140

연속 평가 CLI가 올바른 관리자 조직 세션과 운영 용량의 범위·수치·기존 한도를 확인하고, 주기당 9개 실행의 보관 공간이 부족하거나 동시 슬롯이 없으면 실행 생성 전에 중단한다. 구체적인 사전 검사 상태를 비공개 보고서와 CLI 요약에 남기며 실패 세션도 종료한다. 용량 관측을 예약으로 해석하지 않으며 실제 생성 시 기존 서버의 원자적 한도 검사를 유지한다. 누락/다른 조직 응답도 실패한다.
