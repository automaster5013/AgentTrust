# 다음 구현 작업

확정된 우선순위(2026-10-03): 사용자는 기업 개발팀의 평가 실행과 릴리스 승인 흐름을 선택했다. 첫 구현은 이 흐름을 기준으로 진행한다.

## 현재 상태와 다음 제품 단계

v0.41까지 아래의 로컬 구현 단위는 완료했다. 다음 제품 단계는 실제 고객의 평가 사례와 성공 기준 확정, 고객 에이전트 어댑터 연결, 기업 인증/권한 운영, 별도 staging과 원격 CI 검증이다. 외부 계정·고객 데이터·배포 환경 연결은 해당 범위가 정해진 뒤 진행한다. 아래 최초 계획과 버전별 기록은 구현 이력으로 보존한다.

## 첫 구현 단위

합성 데이터셋을 등록하고 모의 에이전트 버전을 평가해 사례별 근거와 게이트 결정을 보여주는 하나의 완결된 흐름을 만든다. 먼저 로컬에서 동작을 확인하고 인증·조직 격리 완료 전 외부 공개를 금지한다.

제안 구조: `apps/web`, `apps/api`, `apps/worker`, `packages/contracts`, `packages/evaluator`, `infra`, `tests`. 워크스페이스와 패키지 선택은 구현 시 지원 버전을 확인해 확정한다.

1. 저장소 개발 규칙·런타임·포맷·CI 기본값과 환경변수 예제를 작성한다. 비밀은 커밋하지 않는다.
2. 버전·사례·실행·규칙 결과·게이트의 계약과 상태 전이를 정의한다.
3. 결정적 evaluator와 mock adapter를 구현한다. 첫 규칙은 필수/금지 문구, JSON 스키마, 도구 허용 정책이다.
4. 고정된 합성 사례로 통과, 업무 회귀, 금지 도구 호출, 실행 오류를 구현한다.
5. 실행 생성/조회와 결과 화면을 연결한다. 원문 출력은 텍스트로 렌더링한다.
6. 다음 단계에서 DB 지속성, 큐 워커, 인증·조직 경계, 감사 이벤트를 연결한다.

## 완료를 판정할 사례

- 동일 버전과 결정적 모의 입력은 동일한 규칙 판정을 반환한다.
- 필수 규칙 실패는 block, 어댑터 오류·필수 증거 누락은 inconclusive다.
- 실행 생성 이후 정책 또는 데이터 변경이 실행 스냅샷을 바꾸지 않는다.
- 입력 출력에 포함된 스크립트가 화면에서 실행되지 않는다.
- 취소·시간 초과·중복 전달은 최종 결과의 중복 확정과 중복 계량을 만들지 않는다(큐 도입 단계).
- 다른 조직의 ID로 실행과 증거에 접근할 수 없다(인증 도입 단계).

## 사용자와 확정할 결정

첫 구매자/주요 시나리오, 기존 에이전트 연결 방법(HTTPS API/SDK/로컬 실행), 민감 데이터 허용 범위, SaaS 또는 고객 환경 설치 요구. 답변 전에는 모의 어댑터와 합성 데이터 기반 평가 코어를 기본 구현 경로로 삼는다.

다음 단계는 6번: PostgreSQL 지속 저장과 마이그레이션, 인증/조직 권한, 작업 큐와 독립 워커, 감사 이벤트. 취소·시간 초과·중복 전달·조직 간 접근 거절 검증은 이 단계의 완료 조건이다. 현재 구현은 상용화 준비 완료 상태가 아니다.

## 두 번째 구현 완료 기록 — 2026-10-04

6번 작업을 완료했다: PostgreSQL 마이그레이션과 지속 저장, 로컬 키/세션 인증, 조직 RLS와 역할, 독립 워커와 영속 큐, lease 복구와 시도 fencing, 취소·시간·사례 예산, 감사·모의 사용량. Docker의 API/DB/워커를 정지·재시작한 뒤 결과와 사용량 보존을 검증했다.

다음 작업은 제한된 외부 HTTPS 어댑터의 SSRF/egress 통제, 버전 비교와 CI 게이트 연동이다. 그 전에 접근 키의 운영용 관리·OIDC 요구를 결정하고 TLS/비밀 관리·백업 복원 설계를 보완한다. 외부 대상 주소·모델 제공자·배포 지역은 아직 결정하지 않았다. 로컬 v0.2를 상용화 준비 완료로 해석하지 않는다.

## 세 번째 구현 완료 기록 — 2026-10-04

조직별 운영자 allowlist와 endpointHash로 고정한 HTTPS 어댑터, 공인 IPv4 DNS 검증/주소 고정/TLS/응답·시간 제한을 구현했다. 기본 worker는 Docker internal 네트워크로 인터넷 경로가 없으며 외부 연결은 명시적 Compose opt-in을 요구한다. 동일 데이터셋·정책의 버전 결과 비교 API/UI, 기대 버전·유효 시간·증거 전체 범위·해시를 확인하는 조회자 키 기반 CI CLI/API를 구현했다. 사용법과 운영 제약은 release-integration.md에 기록했다.

다음 구현 단위는 운영용 프로젝트 범위 서비스 자격증명과 만료/철회, CI 승인 감사·아티팩트, 백업/복원 검증이다. 외부 대상과 OIDC 제공자, 배포 지역은 미정이다. 실제 외부 호출과 원격 CI 배포를 완료했다고 해석하지 않는다.

## 네 번째 구현 기록 — 2026-10-04 자율 개발

프로젝트 범위 CI 전용 키(만료·철회·발급자 상태 확인), 단일 게이트 경로 권한, append-only 릴리스 검증 기록과 JSON 아티팩트, 관리자 키 관리/프로젝트 검증 기록 UI를 구현했다. DB 스냅샷 기반 dump와 별도 DB 복원 roundtrip의 데이터 지문·RLS·연결 차단을 검증했다. 사용법은 ci-operations.md와 backup-recovery.md를 따른다.

다음 우선순위: 승인 검증 요청의 중복 처리·호출/저장량 통제, 키·승인 이력의 프로젝트 선택/페이지 조회, 백업 암호화와 복원 권한 검증 확대, 신뢰 가능한 승인 아티팩트의 서명 설계. OIDC/원격 runner는 제공자와 배포 대상이 정해지기 전 연결하지 않는다.

## 다섯 번째 구현 기록 — 자율 개발

승인 검증의 호출 주체·프로젝트별 중복 방지, 병렬 전달의 단일 기록/감사, 과거 승인 재사용 시 상태·유효 시간 재검증, 조직별 호출·저장량 상한을 구현했다. 세션의 프로젝트 선택과 CI 키의 프로젝트 고정, 늦게 도착한 응답의 화면 덮어쓰기 방지를 추가했다.

다음 단위는 백업 암호화·복원 보안 속성 검사와 DB 인증 함수의 최소 권한화다. 이어서 프로젝트와 에이전트/정책 버전 관리 UI, 승인 아티팩트 서명과 운영 준비 점검을 진행한다. 실제 OIDC/외부 API/배포는 여전히 비활성 상태다.

읽기 전용 demo:preflight로 런타임·로컬 파일/키·Compose 서비스/포트·API health를 확인하고 실패 단계와 다음 조치를 표시한다. 구조 점검과 실제 인증/평가 성공을 구분한다. 시연 안내와 CI에 연결했다. 새 세션·평가·정책·파일을 만들지 않으며 서비스를 변경하지 않는다.

## v0.47 완료 — 실행 ID 직접 조회

시연 명령의 실행 UUID를 화면에 붙여 넣어 현재 프로젝트의 평가 근거를 직접 조회한다. 유효한 UUID만 요청하고 API 접근 확인 전에는 기존 선택을 유지한다. 목록 필터를 유지하며 중복 클릭·다른 실행 선택·워크스페이스 변경 뒤의 늦은 응답을 차단한다. 권한 검사나 새 조회 API는 추가하지 않고 기존 인증된 실행 조회를 사용한다.

## v0.48 완료 — 현재 최종 게이트 기록 저장

최종 확인 화면에서 해당 실행에 결합된 artifact·artifactHash·signature를 기존 receipt:verify 형식으로 바로 저장한다. 통과·차단을 모두 지원하고 실행/선택/조직 범위·요청 세대에 묶어 이전 응답을 다운로드하지 않는다. 검토 새로고침과 재검증 시작도 이전 기록을 무효화한다. 다운로드 자체는 암호학적 검증이나 현재 배포 허용이 아니다.

## v0.49 완료 — 최종 게이트의 선택적 회귀 비교

기준 실행 UUID를 최종 게이트에 포함하고 비교 통과·회귀 차단을 표시한다. 기본값은 제외하며 잘못된 ID와 후보 자신은 요청하지 않는다. 기준/옵션 변경과 워크스페이스 변경은 이전 판단·다운로드 및 늦은 응답을 무효화한다. 원본 서명 기록은 후보와 기준에 모두 결합된 경우에 저장한다. 기존 서버의 비교·프로젝트 권한 검사를 사용한다.

## v0.50 — 최근 기준 실행 선택

최종 게이트에서 최근 완료 실행 최대 100개 중 후보 자신을 제외하고 기준 UUID를 선택한다. 목록은 호환성·통과를 보장하지 않으며 실제 게이트에서 확인한다. 직접 입력과 목록 새로고침은 입력한 UUID를 유지한다. 기준 선택은 이전 판단과 다운로드를 무효화하고 워크스페이스 변경은 목록을 비운다.

## v0.51 — 비교 판정과 관리자 승인 분리

최종 게이트에서 비교의 evaluationPassed와 전체 배포 허용을 구분한다. 관리자 검토 정책은 비교 통과와 승인 대기를 동시에 표시할 수 있다. 비교 가능 근거가 부족하면 미완료로 표시하며, 변경·회귀 규칙 수와 최대 10개 회귀 세부를 텍스트로 보여준다. 전체 근거는 원본 검증 기록 JSON에 유지한다. 서버 판단이나 승인 권한은 변경하지 않는다.

## v0.52 — 회귀 사례 근거로 이동

최종 비교의 회귀 규칙에서 후보의 정확한 사례로 이동한다. 부분 문자열 검색 대신 사례 ID를 정확히 선택하고 기존 검색·필터를 해제한다. 선택 해제 또는 검색·필터 변경으로 전체 탐색에 복귀한다. 요약·판정·원본 JSON은 전체 실행 기준을 유지한다. 이전 링크는 기준·검토·실행·워크스페이스 변경 뒤 사용할 수 없다.

## v0.53 — CI 입력 선검증

릴리스 CLI는 후보·세 버전 UUID와 선택적 기준/프로젝트 UUID, 검증 키 형식, 비어 있지 않은 접근 키, 유효 시간 범위를 네트워크 요청 전에 확인한다. 후보 자신은 기준으로 지정할 수 없다. 잘못된 설정은 고정 오류와 종료 코드 2로 종료하며 인증 요청이나 서버 기록을 만들지 않는다. UUID 존재·프로젝트 접근 권한·근거·서명은 기존 서버 및 영수증 검증이 확인한다.

## v0.54 — CI 응답 의미 검증

CLI는 해시가 일치하더라도 판정과 배포 허용의 모순, 잘못된 사유 목록, 통과 응답의 차단 사유를 거절한다. 기준 요청은 비교의 후보·기준 ID와 결합하고, 전체 통과는 비교 가능 근거와 비교 평가 통과를 요구한다. 관리자 정책의 evaluationPassed와 별도 승인을 구분한다. 이 검사는 서버 근거·권한 검사나 신뢰 공개키 서명 검증을 대체하지 않는다.

## v0.55 — CI 검증 기록 파일 저장

`AGENTTRUST_RECEIPT_OUTPUT_FILE`을 지정하면 검증된 응답의 원본 artifact·artifactHash·선택적 signature를 JSON 파일에 저장한다. 통과·차단을 모두 저장하며 기존 파일은 덮어쓰지 않는다. 부모 디렉터리는 미리 준비하고 파이프라인 실행별 고유 경로를 사용한다. 저장 실패는 종료 코드 2로 처리하여 성공으로 진행하지 않는다. 파일 저장 자체는 서명 검증·현재 배포 권한 확인을 대체하지 않는다. 신뢰 공개키 검증에는 기존 `AGENTTRUST_RECEIPT_PUBLIC_KEY_FILE`을 함께 지정한다.

## v0.56 — 실제 CLI 프로세스 계약 검증

루프백 합성 서버와 실제 Node 자식 프로세스로 환경변수 전달·서명 검증·JSON 저장·표준 출력·종료 코드를 확인한다. 통과 0, 차단 1, 저장 실패/모순 응답/잘못된 입력 2를 검증한다. 기존 파일은 보존하고 실패 응답은 저장하지 않는다. 외부 서비스나 실제 배포를 호출하지 않는다.

## v0.57 — CI 응답 읽기 제한

릴리스 CLI는 응답 스트림을 최대 8 MiB까지 읽고 UTF-8 및 JSON을 검사한다. 크기 초과 시 스트림 읽기를 취소하며, 잘못된 응답은 검증·파일 저장으로 진행하지 않고 종료 코드 2를 반환한다. 분할된 다중 바이트 UTF-8을 지원한다. 기존 요청 타임아웃·루프백 URL·리디렉션 거절을 유지한다.

## 포트폴리오 기술 설명 갱신 — v0.57 기준

기술 설명의 고정 CI 기준선을 v0.57의 218개 테스트와 네 단계 성공 실행으로 갱신했다. 비교·승인 분리, 정확한 회귀 사례 이동, CI 입력·응답·스트림 제한·원본 저장을 코드/테스트 근거에 연결했다. 준비 후 8분 발표 구성을 추가했다. 제품 버전·기능은 변경하지 않았다.

## 포트폴리오 화면 증거 공개

로컬 브라우저의 합성 화면 3개를 검토해 공개 문서에 연결했다. 비교 통과·승인 대기, 정확한 회귀 사례 이동, 반려 후 새 게이트 차단을 촬영 버전과 함께 표시한다. 이미지에는 비밀/고객 데이터가 없으며 원본 서명 기록과 실행 보고서는 로컬에 유지한다. 제품 버전은 v0.57을 유지한다.

## v0.58 — CI 응답의 지정 프로젝트 결합

`AGENTTRUST_PROJECT_ID`를 지정하면 CLI는 반환된 artifact.projectId가 같은 UUID인지 추가 확인한다. 다른 프로젝트 또는 프로젝트 필드가 없는 응답은 해시가 일치해도 거절한다. 지정하지 않은 기존 프로젝트 키 경로는 서버의 고정 범위를 사용한다. 이 검사는 서버 권한·조직 검사 및 신뢰 공개키 검증을 대체하지 않는다.

## v0.59 — 신뢰 공개키 선검증

신뢰 키를 제공한 경우 CLI는 인증 요청 전에 SPKI PEM 형식의 Ed25519 공개키인지 확인한다. 빈 값·손상된 PEM·지원하지 않는 알고리즘·private key 입력은 고정 오류로 거절한다. 정상 공개키의 출처 신뢰는 운영자가 별도로 확보해야 하며 실제 영수증 서명은 응답 후 다시 확인한다. 키를 지정하지 않은 기존 해시 검증 경로는 유지한다.

## v0.60 — CI UUID 정규화

유효한 후보·기준·프로젝트·세 버전 UUID는 요청 전에 소문자로 정규화한다. 대문자 UUID가 PostgreSQL의 소문자 응답과 달라 성공한 게이트를 오류로 판단하는 일을 방지한다. 검증 키와 접근 키는 변환하지 않으며 공백·잘못된 UUID·후보와 같은 기준은 계속 거절한다. 호출자가 전달한 객체는 변경하지 않는다.

## 저장소 첫 화면 정리 — v0.60 기준

README를 제품 가치·구현 흐름·합성 화면·재현 명령·고정 CI 근거·운영 문서 순서로 정리했다. 촬영 버전과 현재 실행을 구분하고 v0.60의 224개 테스트 및 네 작업 성공 CI를 고정 기준선으로 연결했다. 실제 고객 모델·SSO/OIDC·상용 운영 등 남은 범위를 명시했다. 제품 버전과 기능은 변경하지 않았다.

## v0.61 — 큰 오프라인 서명 기록 검증

온라인 응답의 8 MiB 제한과 오프라인 파일의 기존 512 KiB 제한 불일치를 수정했다. 오프라인 검증은 최대 16 MiB 스트림 읽기와 엄격한 UTF-8 디코딩을 사용한다. 실제 CLI로 큰 합성 서명 기록의 성공·변조 거절을 검증하고 정확한 크기 경계와 손상·누락 파일의 실패를 확인한다. 서명 신뢰와 과거 증거 의미는 유지한다.

## v0.62 — CI 기록 저장과 오프라인 한도 일치

기록 저장·오프라인 검증의 16 MiB 제한을 공유한다. 들여쓰기 팽창 시 압축 JSON으로 저장하며 초과한 기록은 파일 생성 전에 거절한다. 큰 합성 artifact를 저장해 실제 오프라인 읽기·서명을 검증하고, 멀티바이트 UTF-8의 초과 및 기존 파일 보존을 확인한다.

## v0.63 — 온라인·오프라인 신뢰 공개키 검사 통합

오프라인 검증에서 private key를 공개키로 자동 추출하던 경로를 거절하고 온라인 선검증과 같은 Ed25519 SPKI PEM 검사를 사용한다. 합성 서명의 matching private key 거절과 public key 성공을 실제 CLI로 확인하며 손상·빈 입력·지원하지 않는 알고리즘을 검증한다. 발급 키와 기존 기록 형식은 변경하지 않는다.

## v0.64 — 세션 CI의 미사용 응답 정리

로그인·로그아웃과 HTTP 거절 응답의 미사용 스트림을 취소한다. 통과·차단·무결성 실패·HTTP 거절·세션 누락·로그아웃 실패에서 스트림 정리와 로그아웃 흐름을 검증했다. 기존 종료 코드와 실패 시 승인하지 않는 동작을 유지한다.
