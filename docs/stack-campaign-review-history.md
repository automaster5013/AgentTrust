# 캠페인 검토 이력

선택한 캠페인의 최근 승인·반려 50개를 순서 내림차순으로 조회한다. 검토 사유·검토자 ID·정책 버전과 해시·기록 시각을 표시한다. 과거 승인은 현재 배포 권한이 아니며 현재 게이트를 별도로 확인한다. 이력 조회는 업무 데이터를 생성하거나 변경하지 않는다.

Java API `GET /api/campaigns/{id}/reviews`는 기존 scoped 트랜잭션과 캠페인 admission 검사를 사용한다. 다른 조직이나 존재하지 않는 캠페인은 404다. Gateway와 Console 프록시는 이 GET을 명시적으로 허용하며 POST 검토 저장 보호와 다른 메서드 거부를 유지한다.

화면은 캠페인·조직·프로젝트를 대조하고 중복 ID·잘못된 순서·크기 초과·손상된 정책/시각을 거부한다. 새 조회와 범위 변경은 이전 기록을 지우고, 10초 요청 제한과 취소된 응답의 세대 검사를 적용한다. 실패한 조회는 승인 상태로 표시하지 않으며 수동 재조회로 복구한다.

로컬 검증: Java·Gateway·Console 후보 빌드, Console 101개 검사와 타입 검사, 조회자/관리자 실제 API와 다른 조직/없는 캠페인 404의 네 검사, 실제 브라우저의 정상 조회·다른 범위 응답 거부·503 복구·지연 응답 거부가 통과했다. 적용 전후 업무 테이블 18개를 보존했다. 첫 브라우저 실패는 Gateway GET 경로 누락으로 수정했으며 실패 기록을 보존했다.

`scripts/stack-campaign-review-history-smoke.py`는 기존 캠페인을 읽고 자체 세션을 종료한다. 원래 스택 CI의 소스와 정확한 게시 이미지 경로에 포함된다. 이 문서의 로컬 결과는 해당 변경의 원격 CI·이미지 전달·서명 검증 완료 또는 상용 배포를 증명하지 않는다.

검토 시각은 UTC ISO 형식(`Z` 또는 `+00:00`)과 실제 달력 날짜를 확인한다. 2월 30일·비윤년 2월 29일·24시·시간대가 없는 값은 거부하며 정상 UTC 응답의 소수점 정밀도는 보존한다. 잘못된 시각이 포함된 응답은 이전 검토 행을 남기지 않는다.

## 이전 검토 기록 페이지 탐색 (2026-10-14 개발)

기존 `GET /api/campaigns/{id}/reviews`의 최근 50개 계약은 보존한다. 별도 `GET /api/campaigns/{id}/reviews/page`와 `/reviews/page/{cursor}`는 50개씩 순서 내림차순으로 읽고, 51번째 행을 조회해 이전 기록 유무를 판별한다. `nextCursor`는 반환한 마지막 행의 순서와 조직·프로젝트·캠페인에 묶인다. 마지막 페이지는 null을 반환한다. 커서는 서명된 권한이 아니며 모든 페이지 요청에서 실제 캠페인 소유 범위와 RLS를 다시 검사한다. 다른 캠페인·조직·프로젝트, 잘못된 domain·비정규 base64·0/음수/JavaScript 안전 정수 범위를 벗어난 순서는 거부한다.

화면은 첫 페이지·이전 페이지·다음 페이지를 제공한다. 응답의 정확한 필드·범위·정렬·중복·요청 경계·마지막 행과 다음 커서의 결합을 검증한다. 요청 중 이전 행을 지우며 시간 초과·503·변조·선택 변경 뒤 늦게 도착한 응답에 이전 승인 기록을 남기지 않는다. 실패하면 최신 기록 조회로 복구한다. 탐색은 최대 100페이지까지이며 최신 기록은 수동 재조회한다. 마지막 페이지 표시는 조회 시점의 경계를 뜻하고 새 기록 추가나 현재 릴리스 허용을 증명하지 않는다.

개발 검증의 51행 페이지 경계와 브라우저 페이지 전환은 명시적 합성 fixture다. 실제 기존 캠페인 API의 읽기·하위 순서 경계·권한 거부 검사와 구분한다. 로컬 설치의 기존 업무 기록을 51개 이상으로 늘리기 위한 쓰기는 수행하지 않는다. 해당 변경의 원격 CI·15이미지·30서명·오프라인 검증 완료는 새 리비전의 전달 기록이 확보된 후 기록한다.

로컬 후보 검증: Java 129개(페이지 경계·커서 5개 포함), Console 104개 및 타입 검사, 세 서비스 Docker 빌드가 통과했다. 실제 기존 캠페인의 읽기 전용 API 7개 검사와 브라우저 2개 검사(기존 범위/시각/늦은 응답 거부 + 명시적 합성 페이지 탐색·경계 재생/503 거부·수동 복구)가 통과했다. 로컬 후보 적용 전후 업무 테이블 18개와 다른 컨테이너 17개는 동일했다. 첫 브라우저 시도는 테스트의 공통 로그아웃 정리와 중복한 자체 로그아웃 때문에 실패했으며 테스트 정리 책임을 일원화한 뒤 통과했다. 실제 외부 운영 배포와 유료 공급자 호출은 수행하지 않았다.

공유 검토 이력 검사기는 승인·반려 결정의 배열/객체 강제 변환을 거부하고 문자열 두 값만 받는다. 단일 평가와 공유하는 화면의 500자 사유는 모바일에서 단락 안에 줄바꿈하며 원래 줄바꿈을 보존한다. 이 보정의 정확한 원격 전달 결과는 해당 새 리비전의 근거로 별도 확인한다.
