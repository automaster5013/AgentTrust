# 불변 버전 폐기와 릴리스 차단

에이전트나 데이터셋 버전을 더 이상 새 평가와 릴리스에 사용하지 않으려면 관리자가 폐기 사유를 기록한다. 원본 버전 내용과 SHA-256, 기존 평가 결과, MinIO 보관본, 과거 서명은 보존한다. 다시 실행하려면 새 버전을 등록한다.

## API와 권한

- `GET /api/versions/{agents|datasets}/{versionId}/lifecycle`: 현재 조직·프로젝트의 상태와 원본 내용 해시를 조회한다.
- `POST /api/versions/{agents|datasets}/{versionId}/lifecycle/retirement`: 관리자만 1~500자의 공백이 아닌 `reason`으로 폐기한다.
- `GET /api/campaigns/{campaignId}/version-lifecycle`: 후보와 고정 비교 기준의 버전 상태를 조회한다.

폐기 기록은 버전별 한 번만 추가할 수 있다. 같은 사유의 재요청은 같은 기록을 반환하고 다른 사유는 409로 거부한다. 외부 조직·프로젝트에는 404, 편집자·조회자의 폐기 요청에는 403을 반환한다. PostgreSQL의 복합 외래키와 강제 RLS로 범위를 묶고 API 데이터베이스 역할에는 UPDATE·DELETE를 부여하지 않는다. 감사 이력에는 `version.agents.retired` 또는 `version.datasets.retired`를 추가한다.

## 실행과 릴리스

새 캠페인은 후보 에이전트·데이터셋, 고정 비교 기준의 에이전트·데이터셋이 모두 활성이어야 생성할 수 있다. 기존 생성 요청의 정확한 멱등 재전송은 과거 캠페인을 반환하며 새 작업을 만들지 않는다. 폐기와 새 생성·현재 판정·관리자 승인은 같은 조직·프로젝트 트랜잭션 잠금을 사용한다. 폐기 시각은 잠금을 얻은 후 `clock_timestamp()`로 기록한다.

이미 완료한 평가가 통과했더라도 관련 버전이 폐기되면 현재 캠페인 게이트는 릴리스를 허용하지 않는다. 관리자 재승인도 409로 거부한다. OPA 정책 1.4.0과 Java의 독립 응답 검증은 상태뿐 아니라 조직·프로젝트·캠페인·후보와 기준의 버전 ID·내용 해시·순서·개수를 확인한다. 필수 평가 실패·누락에 대한 기존 규칙도 유지한다.

## 서명과 화면

새 현재 판정은 schema 3, 새 과거 관측 기록은 schema 4로 `campaign-version-lifecycle-v1` 증거를 서명한다. 기준이 없는 캠페인은 두 버전, 기준이 있는 캠페인은 네 버전을 포함한다. 폐기 시각이 관측보다 미래이거나 폐기 상태와 배포 허용이 모순되면 브라우저와 독립 공개키 CLI가 거부한다. 이전 서명 계약은 원래 바이트로 검증한다. 과거에 활성이었던 기록은 과거 증거로 유효하며 현재 권한을 부여하지 않는다.

Next.js 화면에서 버전 상태 확인·관리자 폐기·폐기 버전 이력 선택 거부·실행 전 활성 검증을 제공한다. 현재 서명 확인과 오프라인 HTML에는 서명 발급 당시 상태를 표시한다. 과거 HTML에는 폐기 사유와 사용자 메모를 넣지 않는다.

같은 화면에서 폐기 응답을 검증하면 선택한 캠페인의 이전 허용 표시와 현재 서명 확인을 즉시 지우고 현재 게이트를 다시 조회한다. 새 조회가 지연되거나 실패해도 이전 허용을 다시 표시하지 않는다. 브라우저 통합 검사는 실제 승인된 합성 캠페인의 폐기를 수행하고, 새 게이트 응답을 지연시켜 이 동작을 확인한다.

## 검증 범위

`python scripts/stack-version-lifecycle-smoke.py`는 자체 합성 버전과 캠페인을 만들어 후보·기준의 에이전트·데이터셋 네 폐기 경로를 확인한다. 실제 Keycloak 권한·RLS·멱등 재전송·새 생성 및 재승인 거부·OPA·Java Ed25519 현재 서명·폐기 전후 과거 서명 번들·독립 공개키 HTML 검증·변조 거부와 세션 로그아웃을 검사한다. 두 경로마다 실제 요청 한도가 자연 만료되도록 기다린다. CI는 소스 통합과 게시 이미지 통합 모두에서 이 검사를 실행한다.

로컬에서 네 경로와 브라우저의 관리자 폐기·선택/실행 거부를 검증했다. CI 결과와 정확한 게시 이미지의 보안·서명 증거는 해당 revision의 실행으로 별도 확인한다. 버전의 자동 유효 기간, 폐기 복원, 운영 신뢰키 폐기·KMS 및 운영 배포 권한은 이 기능의 구현 범위가 아니다.
