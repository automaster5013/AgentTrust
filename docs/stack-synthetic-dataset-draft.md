# 합성 고정 시나리오 예제 초안

4310의 예제 초안을 준비한 뒤 수정·등록하는 작업 흐름 중, 현재 4320 고정 시나리오 데이터셋 계약에서 가능한 부분을 제공한다. **기존 connector 수용 프로필 전체 이전은 아니다.** 기존 프로필의 두 mock 사례·다섯 임의 규칙(contains/not_contains/allowed_tools/json_schema 등)과 관리자 정책 초안은 별도 미완료다. 이를 고정 통과 시나리오와 동등하다고 취급하지 않는다.

`SyntheticDatasetDraftWorkspace`는 편집자·관리자의 명시적인 예제 준비로 네 사례(pass/block/missing_evidence/error)를 로컬 초안에 넣는다. 처음에는 필수 통과 하나와 선택 사례 세 개이며 사용자가 식별자·시나리오·필수 여부를 수정한다. 기본 예제는 실제 업무 규칙·모델 품질·정책 수용 검증이 아니다. 준비 시 네트워크 요청·저장·평가가 없으며 기존 CampaignWorkspace의 작성 중인 사례·에이전트·관리자 승인 선택을 변경하지 않는다.

준비된 초안은 다시 준비 버튼으로 덮어쓰지 않는다. 명시적인 지우기 후 다시 준비할 수 있다. 사용자가 이름·버전을 입력하고 별도로 등록할 때 기존 CSRF GET 및 editor/admin POST versions/datasets를 사용한다. 새 API·스키마·권한·정책 설정을 추가하지 않는다. 불변 좌표와 같은 내용의 재확인은 기존 ID, 다른 내용은409로 처리하는 원래 서버 계약을 따른다. 최대8개·식별자 유일·필수 사례 하나 이상의 기존 정의 검증을 datasetDefinition으로 추출해 공유한다. 저장 ID나 해시를 지어내어 초안에 부여하지 않는다.

등록 응답은 기존 verifiedDatasetVersion으로 scope·실제 정의 해시를 검증하고 제출한 이름/버전/정의/모든 사례와 정확히 결합한 뒤 확인한다. 조회자는 준비와 등록을 수행할 수 없다. scope·actor·role 변경은 초안을 제거하고 늦은 등록 응답은 표시하지 않는다. 다른 작업으로 비활성화되면 요청을 취소하고 불확실한 저장의 재확인을 안내한다. 실패·치환·409는 기존 초안을 보존한다. 등록 뒤에도 평가·검토·서명·배포를 자동 실행하지 않는다.
