# 단일 평가의 승인·반려 이력

선택한 평가에서 검토 사유·검토자 ID·정책 버전/해시·UTC 기록 시각을 최신순으로 읽는다. 과거 승인은 현재 배포 권한이 아니며 현재 게이트는 별도로 다시 확인한다. 조회자도 읽을 수 있으며 평가나 검토 기록을 새로 만들지 않는다.

기존 `GET /api/runs/{id}/reviews`의 최근 50개 배열 계약과 POST 승인·반려 경로를 보존한다. 새 `GET /api/runs/{id}/reviews/page` 및 `/reviews/page/{cursor}`는 정확한 조직·프로젝트·평가 ID, 한도 50, 순서 기준, `deploymentAuthority:false`, 다음 커서 또는 null을 반환한다. 서버는 매번 해당 평가 소유 범위와 RLS를 검사하고 51번째 행으로 이전 이력 존재 여부를 확인한다. 반환한 마지막 순서보다 작은 기록만 다음 페이지에 포함한다.

평가 커서는 `RRV` domain이며 캠페인의 `CRV`와 구분한다. 다른 평가·조직·프로젝트·커서 domain, 0/음수/안전 정수 초과 순서, 비정규 base64를 거부한다. 커서는 읽기 경계이며 서명된 증거나 권한이 아니다. 임의 경계가 업무 권한을 늘리지 않는다.

공유 검토 이력 화면은 정확한 응답 필드·정렬·중복·UTC 날짜·정책 해시·요청 경계와 다음 커서의 마지막 행 결합을 검사한다. 캠페인/평가·조직·프로젝트·로그인 사용자 변경 및 비활성화는 기존 행과 페이지 상태를 지우고 진행 요청을 취소한다. 10초 제한·지연 응답 거부·503 및 변조 후 수동 재조회 복구를 제공한다. 사유는 텍스트로 렌더링한다. 페이지 탐색은 100페이지까지이며 조회 중 추가되는 최신 기록은 첫 페이지를 다시 조회한다.

실제 기존 평가의 읽기·하위 순서 경계·다른 조직/없는 평가·익명 조회 및 조회자 쓰기 거부는 `scripts/stack-run-review-history-smoke.py`로 확인한다. 소스와 정확한 registry 이미지 CI 경로에 포함한다. 51행 탐색의 단위/브라우저 fixture는 명시적인 합성 응답으로 검증하며 기존 설치의 업무 기록을 늘리지 않는다. 구현·로컬 후보 적용·정확한 리비전의 CI와 게시 이미지 전달·운영 배포 준비는 별도 결과로 기록한다.

로컬 검증: Java 136개(평가 커서·페이지 7개 포함), Console 106개 및 타입 검사, 세 서비스 후보 빌드가 통과했다. 실제 읽기 전용 API 8개 검사는 동일한 기존 기록·하위 순서 경계·다른 domain/평가/조직·익명/조회자 권한과 자체 세션 정리를 확인했다. 브라우저 검토 이력 회귀 3개는 캠페인 2개와 평가 1개이며 평가 검사는 실제 조회와 명시적 합성 페이지·치환·XSS 텍스트 렌더링·지연 응답 거부·503 복구를 구분한다. 적용 전후 업무 테이블 18개와 다른 컨테이너 17개는 동일했다. 운영 배포·유료 공급자 호출은 수행하지 않았다. 원격 CI와 정확한 게시 이미지 결과는 별도 전달 근거를 따른다.

추가 부정 입력과 모바일 경계: 검토 결정은 문자열 `approved`/`rejected`만 허용하며 단일 값 배열·중첩 배열·null·객체의 문자열 변환을 허용하지 않는다. 공백 없는 500자 사유는 검토 이력의 단락 안에서 줄바꿈하고 원래 줄바꿈도 보존한다. 375px 브라우저에서 명시적 합성 500자 입력의 가로 넘침 거부 검사와 배열 결정 응답의 이전 행 제거를 확인한다. 100페이지 탐색 한도에 도달하면 화면에 그 제한을 명시한다.
