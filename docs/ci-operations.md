# 프로젝트 CI 자격증명과 검증 기록 — v0.4

관리자는 화면의 ‘프로젝트 CI 접근 키’에서 프로젝트·키 이름·유효 시간(60초~30일)을 선택해 발급한다. 원문은 발급 응답에서 한 번만 제공한다. 목록·DB·감사 기록은 키 원문을 보존하지 않는다. 화면에서는 마스킹하고 닫기·로그아웃 시 메모리의 입력값을 지운다. 키 복사 이후 운영체제 클립보드 보존은 사용자가 관리한다.

`POST /v1/ci-credentials`: `{ name, projectId, ttlSeconds }`, 관리자 세션 필요. `GET /v1/ci-credentials`는 관리자에게 메타데이터만 반환한다. `POST /v1/ci-credentials/:id/revoke`는 반복 요청에도 감사 이벤트를 중복하지 않는다. 발급자 관리자 멤버십이 비활성화되거나 관리자 역할을 잃으면 해당 키도 인증되지 않는다.

CI 키는 `atci_` 접두어와 256비트 무작위 비밀로 구성하고 SHA-256만 DB에 저장한다. 키는 하나의 조직·프로젝트에 고정된다. `Authorization: Bearer <key>`로 `POST /v1/release-gate`만 호출할 수 있다. 카탈로그·실행 근거·사용자 정보·키 관리·감사 목록 등 다른 보호 경로는 거절한다. 키를 CI secret으로 주입하고 명령 인수·저장소·로그에 넣지 않는다. 기존 로컬 조회자 키를 쓰는 CLI 호환 경로도 유지하지만, CI에는 범위가 좁은 전용 키를 사용한다.

`npm run release:gate`의 환경변수는 release-integration.md를 따른다. CLI는 서버의 판정과 아티팩트, 요청 버전/실행 ID 일치와 해시를 확인한다. 오류는 종료 코드 2, 차단은 1, 검증 통과는 0이다. JSON 출력에는 키나 원문 평가 응답이 없다. 출력물을 파이프라인 아티팩트로 저장할 수 있다. 0을 확인한 다음에만 별도의 배포 작업을 진행한다.

판정은 DB 시간과 프로젝트 범위의 불변 실행을 사용한다. 키를 트랜잭션 안에서 재확인하고 잠가, 철회와 검증을 순서대로 처리한다. 이미 진행 중인 검증은 완료될 수 있으며 이후 요청은 거절된다. 기대 버전 오류·유효 시간 초과·증거 누락·회귀는 차단한다.

통과와 차단은 `release_receipts`에 append-only로 저장하며 `ci.release.checked` 감사 이벤트에 연결한다. 아티팩트는 요청, 판정, 조직/프로젝트, 확인 시간, 후보/기준 실행의 스냅샷·결과 해시와 자체 해시를 포함한다. 일반 세션은 자신의 프로젝트에서 `GET /v1/release-receipts`와 `GET /v1/release-receipts/:id`로 조회·JSON 저장할 수 있다. 조회 시 DB에 저장된 해시를 다시 검증한다.

v0.8부터 신규 기록에는 Ed25519 서명도 포함한다. 독립적으로 신뢰한 공개키로 발급자·무결성을 검증하는 절차는 receipt-signatures.md를 따른다. 기존 서명 없는 기록은 해시 기반 손상 확인만 제공한다. 저장한 기록은 과거 검증의 근거이고 재사용 가능한 배포 권한이 아니다. 배포 직전 새로 게이트를 확인해야 한다. 원격 runner 연결·OIDC·운영 KMS와 승인 보존 정책은 후속 단계다.

인증 전 조직 식별은 제한된 DB 함수 하나로 수행한다. PUBLIC 실행 권한을 철회하고 고정 search_path와 완전한 테이블 이름을 사용한다. [PostgreSQL SECURITY DEFINER 지침](https://www.postgresql.org/docs/current/sql-createfunction.html)을 따른다. 조직 RLS와 프로젝트 조건은 저장·조회 경로에 적용한다.

## v0.5 중복 처리·범위·제한

`Idempotency-Key` 헤더는 8~100자의 영문/숫자/밑줄/하이픈을 받는다. 조직·프로젝트·호출 주체(서비스 키 또는 멤버십) 안에서 같은 키와 같은 요청을 재전송하면 원래 기록과 아티팩트를 반환하고 감사 기록을 중복하지 않는다. 다른 요청은 409다. 재전송할 때도 키의 유효성과 현재 평가 상태·유효 시간을 다시 확인하며 판정이 달라졌다면 409로 거절한다. 새로운 평가 판단은 새 중복 방지 키를 사용한다.

CLI는 기본적으로 매 호출에 새 키를 생성한다. 동일 파이프라인 요청의 재시도에서는 `AGENTTRUST_CHECK_KEY`를 고정한다. 같은 요청을 오래 뒤에 재사용해 과거 통과 판정을 승인으로 취급하지 않는다. 조직당 새 검증 기록은 분당 120개, 총 100,000개로 제한하며 초과는 429다. 이전 기록 재조회는 저장량을 늘리지 않는다. 기록 보존/운영 삭제 정책은 별도로 확정해야 한다.

세션 사용자는 화면의 ‘현재 프로젝트’ 선택 또는 `X-AgentTrust-Project` 헤더로 자신의 조직 내 프로젝트를 선택할 수 있다. 카탈로그·평가 실행·비교·릴리스 기록은 선택한 프로젝트로 제한한다. CI 서비스 키는 발급받은 프로젝트에 고정되며 헤더로 다른 프로젝트에 연결할 수 없다. 기존 세션 키를 쓰는 CLI에는 `AGENTTRUST_PROJECT_ID`를 지정할 수 있다. 조직 감사·모의 사용량은 조직 전체 값이며 관리자 화면에서 명시한다.

화면은 프로젝트 전환 시 결과와 키 원문을 지우고, 이전 요청이 늦게 도착해 현재 화면을 덮어쓰지 않도록 요청 범위를 확인한다. 키를 발급하는 동안에는 프로젝트 전환·로그아웃을 잠시 비활성화해 한 번만 표시되는 키를 놓치지 않도록 한다.

## v0.9 조회와 발급량 제한

CI 키 목록은 현재 프로젝트로 제한한다. 검증 기록과 키 목록의 GET 경로에 limit=1..100 및 cursor를 지정하면 items/nextCursor 응답을 제공한다. 화면은 25개씩 조회한다. Cursor는 조직·프로젝트와 생성 시간의 마이크로초 정밀도·ID에 고정된다. 다른 프로젝트/조직의 cursor, 중복·알 수 없는 query 필드와 범위 밖 limit는 400이다. Query 없는 기존 호출은 배열 응답을 유지한다.

CI 키 발급은 조직당 분당 20개, 활성 100개, 전체 이력 10,000개로 제한한다. 철회로 분당 발급 제한을 초기화할 수 없다. 제한 초과는 429이며 기존 키나 이력은 삭제하지 않는다.

## GitHub 파이프라인 연결

현재 GitHub Actions에서 전체 검증 후 GHCR 이미지를 발행한다. 원격 실행 성공과 고정 digest 기반 수동 배포 준비는 [GitHub 전달 문서](github-delivery.md)를 따른다. 서버 자동 배포는 활성화하지 않았다.

## v0.53 — CI 입력 선검증

릴리스 CLI는 후보·세 버전 UUID와 선택적 기준/프로젝트 UUID, 검증 키 형식, 비어 있지 않은 접근 키, 유효 시간 범위를 네트워크 요청 전에 확인한다. 후보 자신은 기준으로 지정할 수 없다. 잘못된 설정은 고정 오류와 종료 코드 2로 종료하며 인증 요청이나 서버 기록을 만들지 않는다. UUID 존재·프로젝트 접근 권한·근거·서명은 기존 서버 및 영수증 검증이 확인한다.

## v0.54 — CI 응답 의미 검증

CLI는 해시가 일치하더라도 판정과 배포 허용의 모순, 잘못된 사유 목록, 통과 응답의 차단 사유를 거절한다. 기준 요청은 비교의 후보·기준 ID와 결합하고, 전체 통과는 비교 가능 근거와 비교 평가 통과를 요구한다. 관리자 정책의 evaluationPassed와 별도 승인을 구분한다. 이 검사는 서버 근거·권한 검사나 신뢰 공개키 서명 검증을 대체하지 않는다.

## v0.55 — CI 검증 기록 파일 저장

`AGENTTRUST_RECEIPT_OUTPUT_FILE`을 지정하면 검증된 응답의 원본 artifact·artifactHash·선택적 signature를 JSON 파일에 저장한다. 통과·차단을 모두 저장하며 기존 파일은 덮어쓰지 않는다. 부모 디렉터리는 미리 준비하고 파이프라인 실행별 고유 경로를 사용한다. 저장 실패는 종료 코드 2로 처리하여 성공으로 진행하지 않는다. 파일 저장 자체는 서명 검증·현재 배포 권한 확인을 대체하지 않는다. 신뢰 공개키 검증에는 기존 `AGENTTRUST_RECEIPT_PUBLIC_KEY_FILE`을 함께 지정한다.

## v0.56 — 실제 CLI 프로세스 계약 검증

루프백 합성 서버와 실제 Node 자식 프로세스로 환경변수 전달·서명 검증·JSON 저장·표준 출력·종료 코드를 확인한다. 통과 0, 차단 1, 저장 실패/모순 응답/잘못된 입력 2를 검증한다. 기존 파일은 보존하고 실패 응답은 저장하지 않는다. 외부 서비스나 실제 배포를 호출하지 않는다.

## v0.57 — CI 응답 읽기 제한

릴리스 CLI는 응답 스트림을 최대 8 MiB까지 읽고 UTF-8 및 JSON을 검사한다. 크기 초과 시 스트림 읽기를 취소하며, 잘못된 응답은 검증·파일 저장으로 진행하지 않고 종료 코드 2를 반환한다. 분할된 다중 바이트 UTF-8을 지원한다. 기존 요청 타임아웃·루프백 URL·리디렉션 거절을 유지한다.
