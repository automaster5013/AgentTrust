## 포트폴리오 소개문

AgentTrust는 에이전트와 데이터셋의 고정 버전을 등록하고, 평가 결과를 사례·규칙 단위의 근거까지 확인하는 프로젝트입니다. 예제 준비부터 버전 등록, 평가 실행, 근거 조회, 관측 결과 저장까지 사용자의 작업 흐름을 연결했습니다.

이번 개발에서는 14개 기능을 구현하고 각 기능의 정확한 소스 버전에 대해 **격리된 합성 후보 환경의 실제 API·브라우저 수용 검증**을 완료했습니다. 조직·프로젝트·역할 경계와 버전 내용·해시를 확인하며, 응답이 불일치하거나 조회에 실패하면 성공으로 표시하지 않도록 설계했습니다.

개발 과정에서는 응답 간 시각 정밀도 불일치와 후보 큐의 저장 용량 한도 문제를 발견했습니다. 검증 조건을 완화하는 대신 응답 표현과 후보 구성의 결함을 수정하고, 회귀 검사와 후속 후보 수용으로 결과를 확인했습니다.

이 성과는 소스와 합성 후보 환경의 검증입니다. **현재 복구 4320 서비스 적용이나 운영 배포를 의미하지 않습니다.** 평가 통과·과거 서명 관측·저장 파일도 현재 배포 권한으로 취급하지 않습니다.

## 구조와 설계 결정

문자열 규칙 평가의 설명용 경로:

Console → 인증 Gateway → Java Core → PostgreSQL

평가 작업 → 전용 NATS subject/consumer → Python 작업자 → 인증된 완료 API → 사례 근거 화면

- **불변 버전과 내용 결합:** 같은 좌표·같은 내용 재확인은 기존 ID를 반환하고 다른 내용은 409로 거부한다. 목록·상세·등록의 좌표와 내용 해시를 대조한다.
- **조직·프로젝트·역할 경계:** 서버의 RLS와 명시 범위 조건, 화면의 응답 결합을 함께 사용한다. 범위·역할·선택 변경 뒤 늦은 응답은 폐기한다.
- **실패와 검증된 0 구분:** 조회 실패를 0건이나 이전 성공으로 표시하지 않는다.
- **평가 의미 구분:** 필수 규칙 실패는 block, 실행 오류·필수 근거 누락은 inconclusive다. 문자열 평가에서 원문을 reason에 복제하지 않는다.
- **관측과 권한 구분:** 과거 결과·서명 관측·저장 파일은 현재 게이트나 운영 배포 권한을 대신하지 않는다.
- **실행 분리:** 기록된 문자열 평가는 별도 큐·모듈·프로필로 연결해 기존 고정·참조 계약을 재해석하지 않는다. 이 설명에 미수용 connector verifier를 포함하지 않는다.

## 실패와 수정 사례

### 응답의 시각 정밀도 불일치

목록·등록 응답과 상세 응답의 시각 정밀도가 달라 올바른 버전도 정확한 좌표 결합에서 거부됐다. 비교에서 시간 필드를 빼는 대신 기존 VersionResponse.exactTimestamp 표현을 해당 응답에 일치시켰다. 로컬 재현·회귀 검사와 후속 후보에서 목록/등록·상세 좌표 일치 및 전체 새 시나리오 통과를 확인했다.

근거: [데이터셋 복사](stack-dataset-copy.md), [예제 초안](stack-synthetic-dataset-draft.md). 첫 실패 원문이 없는 범위의 다른 원인을 소급 단정하지 않는다.

### 후보 큐의 예약 용량과 서버 한도

세 파일 스트림의 max_bytes 합계 48MiB가 후보 생성 서버의 기존 32MiB 한도를 초과하는 소스 결함을 확인했다. 실제 서비스 설정을 바꾸지 않고 향후 합성 후보 생성 한도만 64MB로 수정했다. 용량 비교 회귀 검사와 후속 후보의 기동·새 시나리오 수용을 확인했다.

근거: [문자열 규칙 평가](stack-recorded-text-rules.md). 최초 기동 실패의 원문이 없어 이 결함을 해당 실행의 유일 원인으로 단정하지 않는다.

실제 캡처 9장·4분 영상·한국어 자막·공개 점검을 완료했다. 로그인 화면·자격증명·토큰·쿠키·개발자 도구 원시 응답·실제 업무내용은 포함하지 않았다. 확인한 저장소 가시성과 파일별 해시·검토 한계는 완료 기록을 따른다. 기존 CI 산출물의 보존 기간·개별 접근 가능성까지 새로 확인한 것은 아니다.

## 재현 조건과 한계

아래는 향후 재현을 위한 조건 설명이며 실행 지시나 현재 환경의 사용 가능성 확인이 아니다.

- 기능별 재현 기준은 위 표의 정확한 SHA와 해당 기능 문서의 수용 시나리오다. 현재 HEAD의 미수용 15번을 제거하거나 숨겨 통과한 상태로 간주하지 않는다.
- 실제 경로 재현에는 격리된 합성 후보의 PostgreSQL·인증·Core·Gateway·Console 및 해당 큐·작업자 연결이 필요하다. 로컬 합성 응답 브라우저 검사는 실제 backend 연결을 대신하지 않는다.
- 예제 준비·등록·실행은 각각 명시 행동이다. editor/admin과 viewer의 허용 범위가 다르며 조회자 등록·실행 거부를 유지한다.
- 문자열 평가 한도는 최대 2사례·사례당 4규칙, 입력·출력 각각 UTF-8 512바이트, 규칙 값 64바이트다. 정규식·코드·외부 모델·실제 도구 호출을 지원하지 않는다.
- 완료 평가 JSON은 정규화된 과거 관측이다. 원본 HTTP/DB 바이트·독립 서명·현재 게이트의 대체물이 아니다.
- 개발용 서명 검증은 운영 독립 신뢰를 수립하지 않는다. 확인한 요청 관측의 저장은 원래 서명 만료 시간을 연장하지 않는다.
- 1440/390px 등 기존 시나리오의 확인을 모든 화면·접근성·전체 장치 수용으로 확대하지 않는다. 현재 HEAD 전체의 신규 통합 수용은 수행하지 않았다. 대표 촬영 경로는 별도 완료 기록의 정확한 소스 구성에서 실제 검증했다.
