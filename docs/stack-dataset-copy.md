# 기존 데이터셋을 새 버전 초안으로 복사

4310의 `dataset-copy` 작업을 4320의 기존 불변 버전 API와 편집자·관리자 권한으로 연결한다. 버전·캠페인 영역에서 원본 데이터셋 ID를 선택하고 **새 초안 불러오기 → 내용·새 키/버전 편집 → 명시적 새 버전 등록**을 수행한다. 복사만으로 저장하거나 평가를 생성하지 않는다.

`GET /api/versions/datasets/{id}`의 현재 조직·프로젝트 범위와 내용 SHA-256을 확인한다. 목록에 있는 원본은 ID·이름·버전·해시·정확한 생성 시각까지 대조한다. 조회 중 사용자가 초안을 수정하면 응답으로 덮어쓰지 않는다. 실패해도 기존 초안을 보존하며 주체·범위·역할 변경 시 초안을 지운다.

지원하는 원본은 현재 4320의 고정 시나리오(최대 8개)와 정답 데이터셋(최대 2개)이다. 원본 평가 계약을 유지하고 필수 사례를 하나 이상 포함한다. 원본과 같은 키·버전으로 저장하지 않으며 다른 좌표의 기존 내용과 충돌하면 409로 거부한다. JSON 초안은 기존 사례 구조만 허용하고 4096자 한도다. 범용 업로드나 4310 데이터 형식의 자동 변환은 포함하지 않는다.

등록은 기존 `POST /api/versions/datasets`와 CSRF 보호·서버 writer 검사를 사용한다. 새 ID·요청 좌표·평가 계약·수정한 사례 전체·내용 해시가 일치하는 응답만 성공으로 표시한다. 응답이 불확실하면 초안을 유지한다. 같은 좌표와 같은 내용의 명시적 재확인은 기존 불변 등록 계약에 따라 같은 버전을 반환하고, 다른 내용은 거부한다. 자동 재시도는 없다.

조회자는 화면의 복사·등록을 사용할 수 없으며 서버 등록도 403이다. 현재 운영 또는 격리 복구 서비스에 새 소스를 적용하지 않는다. DB 스키마·계정·인증 설정 변경은 없다.

검증은 초안 계약과 응답 결합, 기존 Java 등록의 writer·충돌·신규 INSERT, 실제 소스 구성요소의 늦은 응답·편집 보존·변조 거부·CSRF·모바일을 포함한다. 별도 합성 후보 CI에서 실제 API 등록·동일 내용 재확인·충돌·원본 불변·조회자 거부를 검증하며 그 결과가 확인되기 전에는 후보 수용 완료로 표시하지 않는다.
